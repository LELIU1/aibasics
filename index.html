1. 为什么要从内存布局开始

大模型里 99% 的性能问题都能归结为一句话：你在搬运字节，而不是在做浮点运算。 而"搬运多少字节"这件事，完全由张量的布局（layout）决定——数学上完全相同的两个矩阵， 摆法不同，速度可以差几倍。

2. stride：布局的数学定义

一个形状为 $(d_0,d_1,\dots,d_{n-1})$ 的张量，其 stride=$(s_0,\dots,s_{n-1})$ 表示：

$$\text{addr}(i_0,\dots,i_{n-1}) = \text{offset} + \sum_k i_k \cdot s_k$$

连续性（contiguous）的判据是 $s_k = \prod_{m>k} d_m$。

A = torch.arange(12.).reshape(3, 4)
A.stride()      # (4, 1)    行主序：走一行跳 4 个数
A.T.stride()    # (1, 4)    转置后：走一列跳 4 个数
A.T.data_ptr() == A.data_ptr()   # True —— 共享内存！

关键结论：

  • transpose / permute / view（某些情况）是 $O(1)$ 的元数据操作，只改 stride，不搬数据。
  • .contiguous() 才是 $O(n)$ 的真正拷贝（一次读 + 一次写）。
  • 很多手写 kernel 假设输入连续；喂给它非连续张量会触发隐式拷贝，白白多一次全量读写。
  • BLAS（torch.mm / @）比较聪明，能直接吃转置视图（因为它把 stride 当成 lda/ldb 参数）。

运行 ch01 第 1 节会打印：连续 GEMM 与转置视图 GEMM 的耗时几乎相同，而 einsum/自定义 kernel 就没这么好运。

布局陷阱速查

操作 是否拷贝 说明
t.transpose(a,b) / t.permute(...) 否 只改 stride
t.view(...) 否（若兼容） 否则抛错，需先 .contiguous()
t.reshape(...) 可能 必要时会悄悄拷贝
t.contiguous() 是 显式物化
t.expand(...) 否 stride=0 的"广播视图"，见 §4

3. einsum：描述线性代数的通用语言

Einstein 求和约定：重复出现的下标被求和；-> 右边是输出下标。

运算 einsum 写法 形状
矩阵乘 ij,jk->ik $(M,K)\times(K,N)\to(M,N)$
batch 矩阵乘 bij,bjk->bik 逐样本独立
注意力分数 bnd,bmd->bnm 对 $d$ 收缩，保留 $n,m$
多头注意力分数 bhnd,bhmd->bhnm 多一个 head 维
外积（秩1矩阵） i,j->ij 线性注意力的核心，见 CH06
外积累加 bnk,bnv->bkv 对 $n$ 收缩 → 状态矩阵，CH06
bilinear form i,ij,j-> 标量，二次型
trace ii-> 对角线和
对角缩放（左） i,ij->ij 等价于 diag(a) @ B
对角缩放（右） ij,j->ij 等价于 B @ diag(a)

读 einsum 的三步法（把它当成"维度记账"）：

  1. 输入里出现、输出里消失的下标 → 被收缩（求和），代价出现在 FLOPs 里；
  2. 输出里出现的下标 → 被保留，其大小乘积 = 输出元素数；
  3. FLOPs $= 2 \times \prod(\text{所有出现过的下标大小})$（若每个下标在每个输入中至多出现一次）。

例：bhnd,bhmd->bhnm 的 FLOPs $= 2 \cdot B \cdot H \cdot N \cdot D \cdot M$， 注意力里 $N=M$ 所以是 $2BHN^2D$ —— 这就是 $O(N^2)$ 的来源。

本书约定：看到 ->nm 就是"每对 token 之间算一个量"（二次复杂度）； 看到 ->kv 或 ->bd 这种不含 $n$ 的输出，就是"状态/汇总"（线性复杂度）。 这个区别是 CH05→CH07 全部优化的总纲。

4. 广播的代价：隐式的外积

PyTorch 的广播（broadcasting）写成 q[:, :, None, :] - k[:, None, :, :]， 结果是形状 $(B, H, N, N, D)$ 的中间张量——它把每一对 $(n,m)$ 的差向量都物化了。

$$ \text{字节数} = B\cdot H\cdot N^2 \cdot D \cdot 4\ \text{(fp32)} $$

实测（fp32，单头）：

$N, d$ 广播中间张量 注意力矩阵本身 倍数
4096, 64 4.29 GB 67.1 MB 64×
8192, 128 34.36 GB 268.4 MB 128×
32768, 128 549.76 GB 4295.0 MB 128×

再乘上 batch 和头数就是天文数字。第一次写的人基本都会 OOM。 （本教程 ch01 第 3 节故意先用"账面记账"演示这个数量级，再用分块真实跑一遍—— 实测分块后峰值 67.1 MB vs 一次性 536.9 MB，省 8× 且结果完全一致。这个 OOM 本身就是最重要的一课。）

对比：

写法 峰值内存 说明
q[:,:,None,:] - k[:,None,:,:] 后逐元素算 $O(BHN^2D)$ ❌ 炸内存
torch.cdist / einsum 后展开 $O(BHN^2)$ ✅ 只存标量分数

5. 算术强度与 Roofline

算术强度（Arithmetic Intensity, AI）：

$$ \mathrm{AI} = \frac{\text{FLOPs}}{\text{Bytes moved}} \quad [\text{FLOP/Byte}] $$

把它和硬件的"峰值算力 / 峰值带宽"比值比较，就能判断算子属于哪一类：

算子 FLOPs 搬运字节 AI 类型
GEMM $(M,N,K)$，大形状 $2MNK$ $\approx 2(MK+KN+MN)$ 随 $\min(M,N,K)$ 增长，常 > 100 计算受限
逐元素（+、ReLU、乘 mask） $n$ $2n$（读+写）或更多 $\approx 0.25$–$1$ 带宽受限
softmax（一行一行） $\approx 3n$ $2n$（其实可融合到 1 遍） $\approx 1$ 带宽受限
LayerNorm / RMSNorm $O(n)$ $2n$ $\approx 1$ 带宽受限
RoPE $O(n)$ $2n$ $\approx 1$ 带宽受限

在 ch01 实测（CPU）：$2048^3$ GEMM 的 AI ≈ 341，逐元素算子 AI ≈ 0.12 —— 差 2800 倍。

推论（贯穿全书）：

  1. GEMM 已经是"好算子"，别去优化它的 FLOPs，要去减少非 GEMM 的访存次数；
  2. softmax / norm / RoPE / 掩码 / 类型转换这些"便宜"算子，在长序列下才是真正的大头；
  3. 把多个带宽受限的算子融合（fusion） 成一个 kernel，让数据只进出 SRAM 一次 —— 这就是 FlashAttention、融合 RMSNorm、融合 RoPE 的全部动机（CH02、CH05）。

6. 分块（tiling）为什么有用

设 SRAM 容量为 $M$ 字节。把 $N\times N$ 的注意力矩阵分块成 $b\times b$ 的块， 每个块需要的 SRAM 是 $O(b\,d)$，而总 HBM 访问次数是

$$ \text{HBM IO} = \Theta!\left(\frac{N^2 d^2}{M}\right) \quad\text{vs}\quad \text{朴素实现 } \Theta(N^2 + Nd) $$

分块不改变 FLOPs，只改变数据重用率：同一块 K/V 被载入 SRAM 后，服务多个 Q 块。 ch01 第 5 节用纯 PyTorch 的分块 GEMM 验证了结果与整块 GEMM 一致（max|Δ| ≈ 6e-5，浮点结合律误差）。

def demo_stride():
    """1. stride：数学上的转置 vs 内存里的拷贝"""
    section("1. stride 与内存布局")
    A = torch.arange(12, dtype=torch.float32).reshape(3, 4)
    print("A =\n", A)
    print("A.stride()      =", A.stride(), "  连续:", A.is_contiguous())
    print("A.T.stride()    =", A.T.stride(), "  连续:", A.T.is_contiguous())
    print("A.T 与 A 共享内存:", A.T.data_ptr() == A.data_ptr())

    # permute 只改元数据，contiguous() 才会真的搬运数据
    x = torch.randn(2, 3, 4)
    for name, t in [("x                 ", x),
                    ("x.transpose(0,2)  ", x.transpose(0, 2)),
                    ("x.permute(2,0,1)  ", x.permute(2, 0, 1))]:
        print(f"  {name} stride={str(t.stride()):<20s} contiguous={t.is_contiguous()}")

    # 教训：很多 kernel 假设连续输入，非连续张量会触发隐式拷贝（多一次读+写）
    v = torch.randn(2048, 2048)
    vt = v.t()
    t_contig = timer(lambda: v @ v)
    t_trans = timer(lambda: vt @ vt)
    print(f"  连续 GEMM: {t_contig:.2f} ms   转置视图 GEMM: {t_trans:.2f} ms  (BLAS 其实能直接吃转置)")

    # 但 einsum/自定义 kernel 就没这么好运
    print("  小结：transpose/permute 是 O(1) 的元数据操作，contiguous() 才是 O(n) 的搬运。")

def demo_einsum():
    """2. einsum：把所有线性代数运算统一到一套脚标记号"""
    section("2. einsum —— 线性代数的通用语言")
    B, N, d = 2, 6, 8            # batch, 序列长, 头维度
    Q = torch.randn(B, N, d)
    K = torch.randn(B, N, d)
    V = torch.randn(B, N, d)
    W = torch.randn(d, d)

    # (a) 矩阵乘法 / 线性层
    check("线性层 bij,jk->bik  ==  Q @ W", torch.einsum("bij,jk->bik", Q, W), Q @ W)

    # (b) batch 矩阵乘
    Xb, Yb = torch.randn(B, N, 4), torch.randn(B, 4, N)
    check("batch 矩阵乘 bnd,bdm->bnm == bmm", torch.einsum("bnd,bdm->bnm", Xb, Yb), torch.bmm(Xb, Yb))

    # (c) 注意力分数 = 批量双线性形式
    S = torch.einsum("bnd,bmd->bnm", Q, K)          # B,N,N
    check("注意力分数 bnd,bmd->bnm == Q@K^T", S, Q @ K.transpose(-2, -1))

    # (d) 加权求和
    O = torch.einsum("bnm,bmd->bnd", S.softmax(-1), V)
    check("加权求和 bnm,bmd->bnd", O, S.softmax(-1) @ V)

    # (e) 外积累加（线性注意力的核心！见 CH06）
    kv = torch.einsum("bnk,bnv->bkv", K, V)         # 把整段序列压成一个 d×d 状态矩阵
    print(f"  外积累加: K,V 形状 {tuple(K.shape)} -> 状态 {tuple(kv.shape)}  "
          f"（N 消失，这就是 O(N) 线性注意力的秘密）")

    # (f) 对角 / trace / 提取对角线
    M = torch.randn(d, d)
    check("trace ii->", torch.einsum("ii->", M), torch.trace(M))
    # (g) 双二次型 q^T M k
    q, k = torch.randn(d), torch.randn(d)
    check("双线性 i,ij,j->", torch.einsum("i,ij,j->", q, M, k), q @ M @ k)
    # (h) Hadamard 积与归约
    check("逐元素乘+求和 ij,ij->", torch.einsum("ij,ij->", M, M), (M * M).sum())
    # (i) 多头注意力一次写全：把 head 维当脚标
    H = 4
    Qh = torch.randn(B, H, N, d)
    Kh = torch.randn(B, H, N, d)
    Vh = torch.randn(B, H, N, d)
    Oh = torch.einsum("bhnd,bhmd->bhnm", Qh, Kh).softmax(-1)
    Oh = torch.einsum("bhnm,bhmd->bhnd", Oh, Vh)
    ref = torch.softmax(Qh @ Kh.transpose(-2, -1), -1) @ Vh   # 本例省略 1/sqrt(d) 缩放
    check("多头注意力 bhnd,bhmd->bhnm 全 einsum 版", Oh, ref)

    print("  einsum 速查：重复脚标=沿该轴相乘并求和；缺失脚标=求和掉；输出脚标=保留")

def demo_broadcast():
    """3. 广播 = 隐式外积。代价：中间张量被真实展开到内存"""
    section("3. 广播的内存代价（为什么 FlashAttention 要避免它）")
    # 真实规模：只算账，不真的分配（否则 OOM —— 这恰恰是重点）
    for N, d in [(4096, 64), (8192, 128), (32768, 128)]:
        temp = N * N * d * 4 / 1e9
        score = N * N * 4 / 1e6
        print(f"  seq={N:>6d}, d={d:>3d}: 广播中间张量 {temp:8.2f} GB, "
              f"注意力矩阵本身 {score:8.1f} MB  → 中间/结果 = {temp*1e9/(score*1e6):.0f}x")

    # 小规模实测：证明它真的会 materialize（用 chunk 方式避免，对比内存峰值）
    N, d, CH = 2048, 32, 256
    q, k = torch.randn(N, 1, d), torch.randn(1, N, d)
    out = torch.zeros(N, N)
    for s in range(0, N, CH):                       # 分块：一次只展开 CH×N×d
        out[s:s + CH] = (q[s:s + CH] - k).pow(2).sum(-1)
    naive = (q - k).pow(2).sum(-1)                  # 一次性展开 N×N×d
    check("分块广播 == 一次性广播", out, naive, atol=1e-4)
    print(f"  分块版峰值中间张量 {(CH*N*d*4)/1e6:.1f} MB vs 一次性 {(N*N*d*4)/1e6:.1f} MB "
          f"→ 省 {N/CH:.0f}x，数学结果完全一致")
    print("  → 这就是 attention 的 O(N^2) 内存墙，CH05 用 FlashAttention 彻底解决")

def demo_arithmetic_intensity():
    """4. 算术强度：FLOPs / Bytes = 每搬 1 字节能做多少次运算"""
    section("4. 算术强度与 roofline 直觉")
    N = 2048
    A = torch.randn(N, N)
    Bm = torch.randn(N, N)
    x = torch.randn(N * N)

    t_gemm = timer(lambda: A @ Bm)
    flops = gemm_flops(N, N, N)
    bytes_gemm = bytes_of(A, Bm) + N * N * 4
    ai_gemm = flops / bytes_gemm

    t_elt = timer(lambda: x * 2.0)
    flops_e = x.numel()
    bytes_e = bytes_of(x) * 2
    ai_elt = flops_e / bytes_e

    print(f"  GEMM   ({N}x{N}x{N}): {t_gemm:8.2f} ms  {flops/1e9:8.2f} GFLOP  "
          f"{flops/t_gemm/1e9*1e3:7.1f} GFLOP/s  算术强度={ai_gemm:7.1f} FLOP/Byte")
    print(f"  逐元素 ({x.numel():>8} 个): {t_elt:8.2f} ms  {flops_e/1e6:8.2f} MFLOP  "
          f"{flops_e/t_elt/1e9*1e3:7.2f} GFLOP/s  算术强度={ai_elt:7.2f} FLOP/Byte")
    print("  结论：GEMM 算术强度高 → 算力受限（好）；逐元素/softmax/归一化 → 带宽受限（坏）。")
    print("  Softmax、RMSNorm、RoPE、激活函数都属于后者，所以优化方向是【融合 kernel】。")


def demo_tiling_effect():
    """5. 分块为什么有效：把工作集塞进 cache"""
    section("5. 分块（tiling）的数值等价性与 cache 友好性")
    N, BS = 1024, 64
    A, B = torch.randn(N, N), torch.randn(N, N)
    C_ref = A @ B

    # 手写分块 GEMM：数学上完全等价（分块矩阵乘法）
    C = torch.zeros(N, N)
    for i in range(0, N, BS):
        for j in range(0, N, BS):
            for kk in range(0, N, BS):
                C[i:i + BS, j:j + BS] += A[i:i + BS, kk:kk + BS] @ B[kk:kk + BS, j:j + BS]
    check("分块 GEMM == A@B（分块矩阵乘法）", C, C_ref)
    print(f"  分块大小 {BS}：每块只需 resident A块+{BS}x{BS} 与 B块+{BS}x{BS}，"
          f"约 {2*BS*BS*4/1024:.0f} KB，能放进 L1/L2")
    print("  这正是 GPU 上 SRAM(≈几十MB共享内存) vs HBM(≈80GB) 的同一套故事 → CH05 FlashAttention")

1. Transformer 的 GEMM 普查

一个标准解码器层（$d{=}4096$, $H{=}32$, $D{=}128$, $f_{ff}{=}14336$, $N{=}2048$, $B{=}8$）里， 所有大矩阵运算的 FLOPs 分布：

部分 表达式 GFLOP 占比
QKV 投影 $X W_{qkv}$ 824.6 18.2%
Attention 分数 $QK^\top$ 274.9 6.1%
Attention 输出 $A V$ 274.9 6.1%
O 投影 $O W_o$ 274.9 6.1%
MLP up + gate $h W_{up}, h W_{gate}$ 1924.2 42.4%
MLP down $a W_{down}$ 962.1 21.2%
合计 4535.5 100%

注意 attention 占比随 $N$ 的剧烈变化（这是长上下文一切优化的根源）：

$N$ attention 其它 占比
2048 549.8 GFLOP 3985.7 12.1%

2. 结合律：换乘法顺序能省一个数量级

矩阵乘法满足结合律 $(AB)C = A(BC)$，但不满足交换律。 FLOPs 却强烈依赖于括号位置：

$$ (M\times K)\cdot(K\times N)\cdot(N\times P) $$

  • $(AB)C$：$2MKN + 2MK\cdots$ 具体为 $2MKN + 2MNP$
  • $A(BC)$：$2KNP + 2MK\cdots$ 具体为 $2KNP + 2MK$

若 $N \gg M,P$（长序列），两者相差巨大。

案例 A：LoRA 的权重合并

$$ y = x W + x\cdot \frac{\alpha}{r} B A = x\left(W + \frac{\alpha}{r}BA\right) $$

  • 不合并：$2\,d_{in}d_{out} + 2\,r(d_{in}+d_{out})$ FLOPs，两次 kernel launch，多一次激活读写；
  • 合并：$W' = W + \frac{\alpha}{r} BA \in \mathbb{R}^{d_{in}\times d_{out}}$，一次 GEMM。

推理阶段必须合并（省掉整条旁路 + 一次逐元素加）；训练阶段不能合并（要保持 $A,B$ 可训、 $W$ 冻结，且合并后反向传播会破坏低秩结构）。

ch02 第 2 节实测 FLOPs：

写法 GFLOP
合并 $W' = W + \frac\alpha r BA$ 8.59
链式 $x \to A \to B$ 8.66
先算 $\Delta W$ 再加（最蠢的写法） 17.72

FLOPs 差别不大（因为 $r$ 很小），真正的收益是少一次 kernel launch、 少一份中间激活的读写、少一次逐元素加。

案例 B：$(QK^\top)V$ vs $Q(K^\top V)$

  • $(QK^\top)V$：$2N^2d + 2N^2d$
  • $Q(K^\top V)$：$2Nd^2 + 2Nd^2$

实测（$N{=}2048, d{=}64$）：$(QK^\top)V$ = 4295.0 MFLOP，$Q(K^\top V)$ = 67.1 MFLOP，省 64×。 但两者并不等价（实测直接换序的最大偏差是 2479.7）—— 只有去掉 softmax 之后才能这么换 （这正是 CH06 线性注意力的全部秘密）：

$$ \mathrm{softmax}(QK^\top)V \ne Q(K^\top V) $$

因为 softmax 是逐行非线性，它卡在中间，把结合律打断。 ch02 明确验证了这个不等价（这是理解"为什么要发明线性注意力"的关键）。

3. 矩阵吸收：把对角/标量"吸"进邻居

这是最划算的优化：零 FLOPs、零访存，纯代数恒等式。

3.1 标量吸收

$$ \frac{1}{\sqrt d} \text{ 可以吸进 } W_Q \text{ 或 } W_K:\quad \frac{q^\top k}{\sqrt d} = \left(\tfrac{1}{d^{1/4}}q\right)^\top\left(\tfrac{1}{d^{1/4}}k\right) $$

3.2 对角吸收（RMSNorm 的 $\gamma$）

RMSNorm：

$$ \mathrm{RMSNorm}(x) = \underbrace{\frac{x}{\mathrm{rms}(x)}}_{\text{归一化}} \odot \gamma $$

$\gamma$ 作用在输入维度上（逐列缩放）。若后面紧跟 $y = \mathrm{RMSNorm}(x)W$，则

$$ (\hat x \odot \gamma) W = \hat x\, (\mathrm{diag}(\gamma)W) = \hat x\, W' \quad\Longrightarrow\quad W'{ij} = \gamma_j W $$

即 $\gamma$ 按列吸收进 $W$ 的行……更准确地说：$W$ 的第 $j$ 行整体乘 $\gamma_j$， 代码写 W * gamma[None, :]（$W$ 形状 $(d_{in}, d_{out})$，$\gamma$ 长度 $d_{in}$）。

⚠️ 这是本教程踩过的坑：广播方向搞反会得到 max|Δ| ~ 1.7e+02。 记住口诀：$\gamma$ 乘在被求和的那一维上。

3.3 softmax 的平移不变性

$$ \mathrm{softmax}(s + c\mathbf 1) = \mathrm{softmax}(s) $$

所以 causal mask 的 $-\infty$ 可以加在任意一侧；而在线 softmax（CH05）正是靠这一点做重缩放。

ch02 第 4 节拿一个 $137.4$ GFLOP 的 GEMM（输出 67 MB）做账：

访存减少 3.0×，FLOPs 一点没变。

实测（CPU）：gelu(add(x)) 分两个 pass 是 17.6 ms，融合成单 pass 是 8.0 ms（2.2×）。

注意这里"不融合"的版本已经是 GEMM 主导（AI 仍有 227），所以只差 3×。 真实的 norm / RoPE / 掩码这些纯逐元素算子，AI 只有 ~1，融合收益会大得多。

5. 头合并：把小 GEMM 变成大 GEMM

多头注意力里，每个头一次 $N\times D \times N$ 的小 GEMM。$H$ 个头就有 $H$ 个小 GEMM， 每个的算术强度都不高（因为 $D=128$ 很小）。

做法：把 head 维挪到 batch 维，用一次 bmm：

# q: (B, N, H, D) -> (H, B*N, D)
q_ = q.transpose(1, 2).reshape(H, B * N, D)
k_ = k.transpose(1, 2).reshape(H, B * N, D)
S = torch.bmm(q_, k_.transpose(1, 2))        # (H, B*N, B*N)

ch02 第 5 节实测（CPU）：32 次小 GEMM 121.5 ms vs 一次 bmm(128 batch) 112.5 ms —— 只快 1.08×。这个数字有点"打脸"，但它恰好说明两件事：

  1. CPU 上 BLAS 本身对单 GEMM 已经很高效，收益主要来自省掉 32 次 kernel launch；
  2. GPU 上差别会大得多：除了 launch 开销，还有"每个小 GEMM 都要把权重重新读一遍" —— 权重访存被重复了 $H$ 次，这才是大头。

所以这个优化的主要价值在 GPU / 小 head_dim 场景，别指望在 CPU 上看到数量级提升。

这也是为什么 GQA（CH04）在 $H_{kv} \ll H$ 时依然要保持"头"这个 batch 维—— 它换来的是 KV Cache 的成倍缩小，而计算侧用 expand 补回来。

def demo_associativity():
    """2. 结合律：换乘法顺序，FLOPs 天差地别"""
    section("2. 结合律 (AB)C = A(BC) 的性能含义")

    # (a) LoRA: y = x (W + B A)^T
    d_in, d_out, r = 4096, 4096, 16
    B_n = 8 * 32
    x = torch.randn(B_n, d_in)
    W = torch.randn(d_out, d_in) * 0.02
    lora_B = torch.randn(d_out, r) * 0.02
    lora_A = torch.randn(r, d_in) * 0.02

    y_merge = x @ (W + lora_B @ lora_A).T          # 先合并权重，再乘
    y_chain = x @ W.T + (x @ lora_A.T) @ lora_B.T   # 链式：低秩路径单独走
    y_dense = x @ W.T + x @ (lora_B @ lora_A).T     # 先算 ΔW 再乘（最差）
    check("LoRA 权重合并 == 链式计算", y_merge, y_chain)
    check("LoRA 权重合并 == 先算 ΔW", y_merge, y_dense)

    f_merge = gemm_flops(B_n, d_out, d_in)
    f_chain = gemm_flops(B_n, d_out, d_in) + gemm_flops(B_n, r, d_in) + gemm_flops(B_n, d_out, r)
    f_dense = gemm_flops(d_out, r, d_in) + gemm_flops(B_n, d_out, d_in) * 2

    print("  → 推理部署一定要 merge LoRA（W' = W + BA），服务时省掉低秩分支；")

def demo_absorb():
    """3. 对角矩阵与标量的吸收：零代价的数学技巧"""
    section("3. 矩阵吸收：把邻近运算揉进权重")
    B_n, d = 4, 512
    x = torch.randn(B_n, d)
    W = torch.randn(d, d)

    # (a) RMSNorm 的 gain 吸收进下一层权重:  (norm(x) ⊙ γ) @ W^T = norm(x) @ (diag(γ) W^T)
    def rmsnorm(x, g, eps=1e-6):
        return x * torch.rsqrt(x.pow(2).mean(-1, keepdim=True) + eps) * g
    gamma = torch.randn(d)
    h = rmsnorm(x, gamma)
    y1 = h @ W.T
    # y = (n ⊙ γ) W^T = n (W·diag(γ))^T，其中 (W·diag(γ))[i,j] = W[i,j]·γ[j]  → 按列缩放
    y2 = rmsnorm(x, torch.ones_like(gamma)) @ (W * gamma[None, :]).T
    check("RMSNorm γ 吸收进 W（按列缩放 W·diag(γ)）", y1, y2)
    print("  注意方向：γ 作用在【输入维度】上 → 缩放 W 的列；若作用在输出维度则缩放行")

    # (b) attention 的 1/sqrt(d) 吸收进 W_q
    H, D = 8, 64
    N = 128
    q = torch.randn(B_n, H, N, D); k = torch.randn(B_n, H, N, D)
    s1 = torch.einsum("bhnd,bhmd->bhnm", q, k) / (D ** 0.5)
    s2 = torch.einsum("bhnd,bhmd->bhnm", q / (D ** 0.25), k / (D ** 0.25))
    s3 = torch.einsum("bhnd,bhmd->bhnm", q / (D ** 0.5), k)
    check("1/√d 拆成两个 1/d^0.25 吸收进 W_q/W_k", s1, s2)
    check("1/√d 整体吸收进 W_q", s1, s3)

    # (c) Softmax 的平移不变性 → 最大值可吸收
    logits = torch.randn(B_n, N, N) * 10
    p1 = torch.softmax(logits, -1)
    p2 = torch.softmax(logits - logits.max(-1, keepdim=True).values, -1)
    check("softmax 平移不变性（为在线 softmax 铺垫）", p1, p2)
    print("  → 同理，RoPE 不能吸收进 W（它依赖 token 位置 m），只能在线算 → CH03")

def demo_head_merge():
    """5. head 合并：把小 GEMM 拼成大 GEMM"""
    section("5. 把 head 维塞进 batch 维 —— 小 GEMM → 大 GEMM")
    Bn, H, N, D = 4, 32, 2048, 128
    Q = torch.randn(Bn, H, N, D)
    W = torch.randn(H, D, D)
    # 写法 A：每个 head 单独一个 GEMM
    outA = torch.stack([Q[:, i] @ W[i].T for i in range(H)], dim=1)
    # 写法 B：把 head 挪到 batch 维，一次 bmm：(H, B*N, D) @ (H, D, D)
    def merged():
        q2 = Q.transpose(0, 1).reshape(H, Bn * N, D)
        return torch.bmm(q2, W.transpose(-2, -1)).reshape(H, Bn, N, D).transpose(0, 1)
    outB = merged()
    check("逐 head GEMM == 合并后 batched GEMM", outA, outB)
    tA = timer(lambda: torch.stack([Q[:, i] @ W[i].T for i in range(H)], dim=1))
    tB = timer(merged)
    print(f"  {H} 次小 GEMM: {tA:.1f} ms  →  1 次 bmm({Bn*H} 个 batch): {tB:.1f} ms  (快 {tA/tB:.2f}x)")
    print("  → GPU 上差别更大：kernel launch 开销 + 每个小 GEMM 都读一遍权重")

CH03

RoPE 旋转位置编码

代码：code/ch03_rope_rotation.py 前置：CH01（einsum）、CH02（矩阵吸收）

1. 核心思想：把位置编码做成"旋转"

传统位置编码是把位置向量加到词向量上：$x_t \to x_t + p_t$。 RoPE 不这样做——它把位置 $m$ 映射成一个旋转矩阵 $\rho(m)$，然后

$$ q_m = \rho(m)\, W_q x_m,\qquad k_n = \rho(n)\, W_k x_n $$

于是注意力分数变成

$$ \langle q_m, k_n\rangle = (\rho(m)W_q x_m)^\top (\rho(n) W_k x_n) = x_m^\top W_q^\top \underbrace{\rho(m)^\top\rho(n)}_{=\ \rho(n-m)} W_k x_n $$

关键恒等式：$\rho(m)^\top \rho(n) = \rho(n-m)$。 分数只依赖相对距离 $n-m$ —— 这就是"相对位置编码"，而且不需要改注意力公式， 只是把 $q,k$ 旋转一下。

2. 二维旋转矩阵 $R(\theta)$ 的代数性质

$$ R(\theta) = \begin{pmatrix}\cos\theta & -\sin\theta\ \sin\theta & \cos\theta\end{pmatrix} $$

性质 公式 含义
正交 $R^\top R = I$ 保范数、保内积（不拉伸不剪切）
行列式 $\det R = +1$ 属于特殊正交群 $SO(2)$，纯旋转无镜像
群同态 $R(\theta_1)R(\theta_2) = R(\theta_1+\theta_2)$ 旋转可加
逆 $R(\theta)^{-1} = R(-\theta) = R(\theta)^\top$ 反向传播就是反向旋转

最后一条在代码里很实用：RoPE 的梯度不需要额外推导，把 $q$ 旋转 $-m$ 即可。

ch03 第 1 节验证 $0^\circ/30^\circ/90^\circ/180^\circ/270^\circ$ 下的 $\lVert R^\top R - I\rVert \approx 10^{-8}$、$\det = +1$。

3. 高维：分块对角 = $d/2$ 个独立旋转平面

$d$ 维空间被切成 $d/2$ 个 2D 平面，每个平面用不同角速度 $\theta_i$ 旋转：

$$ \rho(m) = R(m\theta_0) \oplus R(m\theta_1) \oplus \cdots \oplus R(m\theta_{d/2-1}) = \mathrm{blkdiag}\big(R(m\theta_i)\big)_{i} $$

其中频率（这就是 LLaMA/Mistral 里的 inv_freq）：

$$ \theta_i = \mathrm{base}^{-2i/d},\qquad i = 0,\dots,d/2-1,\quad \mathrm{base}=10000 $$

为什么是几何级数？ $\theta_i$ 从 $1$ 衰减到 $\mathrm{base}^{-1}\approx 10^{-4}$，跨度 4 个数量级：

  • 高频平面（$i$ 小，$\theta\approx 1$）：转得快 → 编码近距离精细差异；
  • 低频平面（$i$ 大，$\theta\approx 10^{-4}$）：转得慢 → 编码远距离粗粒度信息。

这跟傅里叶基/小波基的思路一致：多尺度分解。

4. 两种内存布局：交错 vs 半分

同一个 $\rho(m)$ 有两种摆法：

交错布局（interleaved，GPT-J / RoFormer 原始）：相邻两个分量组成一对

$$ (x_0,x_1,x_2,x_3,\dots) \Rightarrow (x_0,x_1),(x_2,x_3),\dots $$

半分布局（half-split，LLaMA / HF 主流）：前后两半配对

$$ (x_0,\dots,x_{d/2-1})\ |\ (x_{d/2},\dots,x_{d-1}) \Rightarrow (x_0,x_{d/2}),(x_1,x_{d/2+1}),\dots $$

两者由置换矩阵 $P$ 共轭关联：

$$ \rho_{\text{half}}(m) = P^\top\, \rho_{\text{int}}(m)\, P,\qquad P^\top P = I $$

代码上，半分布局只要一次 chunk(2, -1)：

def rotate_half(x):
    x1, x2 = x.chunk(2, -1)                 # 前半 / 后半
    return torch.cat((-x2, x1), -1)

def apply_rope(x, cos, sin):                # cos/sin 形状 (..., d/2)
    return x * cos.cat((cos, cos)) + rotate_half(x) * sin.cat((sin,sin))

或者更省：直接

t1, t2 = t.chunk(2, -1)
out = torch.cat((t1*cos - t2*sin, t2*cos + t1*sin), -1)     # cos/sin: (..., d/2)

5. 复数视角

半分布局天然是复平面上的相位乘法。把 $(x_{i}, x_{i+d/2})$ 视为 $z_i = x_i + \mathrm{i}\,x_{i+d/2}$：

$$ z_i \mapsto z_i \cdot e^{\mathrm{i} m\theta_i} $$

实数形式 复数形式
$2\times2$ 旋转矩阵 单位模复数 $e^{\mathrm{i}m\theta}$
$R^\top R = I$ $\lvert e^{\mathrm{i}\phi}\rvert = 1$
$R(\theta_1)R(\theta_2)=R(\theta_1+\theta_2)$ $e^{\mathrm{i}\phi_1}e^{\mathrm{i}\phi_2}=e^{\mathrm{i}(\phi_1+\phi_2)}$
$\rho(m)^\top\rho(n)=\rho(n-m)$ $\overline{e^{\mathrm{i}m\theta}}\,e^{\mathrm{i}n\theta} = e^{\mathrm{i}(n-m)\theta}$

复数形式在实现上更省：torch.view_as_complex 后一次复数乘法即可（很多推理框架这么做）。

7. 长上下文外推：NTK-aware 与 YaRN

训练长度 $L_{train}$，想外推到 $L_{test} = s\, L_{train}$。

NTK-aware scaling

直接改基底（高频拉伸得多、低频拉伸得少，等价于"非均匀插值"）：

$$ \mathrm{base}' = \mathrm{base}\cdot s^{\,d/(d-2)} $$

YaRN（ramp 插值）

对不同频带用不同强度的插值，中间用斜坡过渡。设波长 $\lambda_i = 2\pi/\theta_i$，比值 $r = L_{train}/\lambda_i$：

$$ \gamma_i = \mathrm{clip}!\left(\frac{r - \alpha}{\beta - \alpha},\ 0,\ 1\right),\qquad \theta_i' = \begin{cases}\theta_i, & \gamma_i = 0\ (r\le\alpha)\ \dfrac{\theta_i}{(1-\gamma_i)/s + \gamma_i}, & \text{otherwise}\end{cases} $$

直觉：

  • $r \le \alpha$（波长短于训练长度 → 已见过足够多周期）→ 不插值，直接外推；
  • $r \ge \beta$（波长长于训练长度 → 从未见过一个完整周期）→ 完全插值；
  • 中间 → 斜坡过渡。

再加一个 attention 温度的修正（$t = 0.1\ln s + 1$）补偿熵的变化。

8. 一个反例：不正交会发生什么

ch03 第 6 节故意用一个非正交的"伪位置矩阵" $A(m)$（比如带上缩放的对角矩阵）替换 $\rho(m)$：

  • $\langle A(m)q, A(n)k\rangle$ 不再只依赖 $n-m$；
  • $\lVert A(m) q\rVert \ne \lVert q\rVert$，点积尺度随位置漂移 → 等价于随位置变化的温度。

这解释了为什么 RoPE 一定要正交：正交是"不改变向量几何、只改变坐标系"的充要条件。

# ------------------------------------------------------- 2. 分块对角 + 布局
def freqs(base, d, device=None):
    """θ_i = base^{-2i/d},  i = 0..d/2-1"""
    i = torch.arange(0, d, 2, dtype=torch.float32)
    return 1.0 / (base ** (i / d))


def build_block_diag_R(m, d, base=10000.0, layout="interleaved"):
    """构造完整的 d×d 分块对角旋转矩阵（教学用，实践中绝不这么干）"""
    th = freqs(base, d) * m
    R = torch.eye(d)
    for j, t in enumerate(th):
        c, s = torch.cos(t), torch.sin(t)
        if layout == "interleaved":
            p, q_ = 2 * j, 2 * j + 1
        else:                                   # half-split
            p, q_ = j, j + d // 2
        blk = torch.tensor([[c, -s], [s, c]])
        R[p, p], R[p, q_], R[q_, p], R[q_, q_] = blk[0, 0], blk[0, 1], blk[1, 0], blk[1, 1]
    return R


def rotate_half(x):
    """半分布局：把后半取负搬到前面 —— 一次 cat 就完成 d/2 个平面的旋转"""
    x1, x2 = x.chunk(2, dim=-1)
    return torch.cat((-x2, x1), dim=-1)


def apply_rope(x, cos, sin):
    """x: (..., d) 半分布局；cos/sin: (..., d)"""
    return x * cos + rotate_half(x) * sin


def demo_block_diag():
    section("2. 分块对角化与两种内存布局")
    d, base = 8, 10000.0
    m = 3
    q = torch.randn(d)

    R_int = build_block_diag_R(m, d, base, "interleaved")
    R_half = build_block_diag_R(m, d, base, "half")
    check("R 是正交矩阵（交错）", R_int.T @ R_int, torch.eye(d))
    check("R 是正交矩阵（半分）", R_half.T @ R_half, torch.eye(d))

    # 置换矩阵：把半分布局换成交错布局
    perm = torch.empty(d, dtype=torch.long)
    perm[0::2] = torch.arange(d // 2)
    perm[1::2] = torch.arange(d // 2) + d // 2
    P = torch.zeros(d, d); P[torch.arange(d), perm] = 1.0   # (P x)[j] = x[perm[j]]
    check("半分/交错布局经置换共轭关联 R_half = P^T R_int P",
          R_half, P.T @ R_int @ P)

    # 高效实现（逐元素）vs 矩阵乘法
    th = freqs(base, d) * m
    cos = torch.cat([th.cos(), th.cos()])       # 半分布局：前后半共用同一组 cos/sin
    sin = torch.cat([th.sin(), th.sin()])
    check("apply_rope(逐元素) == 分块对角矩阵乘法", apply_rope(q, cos, sin), R_half @ q)

    print("  分块对角矩阵视角：ℝ^d = ⊕_{i} ℝ^2 (d/2 个旋转平面)，第 i 个平面以角速度 θ_i 转")
    print(f"  θ_i = base^(-2i/d): {[f'{t:.5f}' for t in freqs(base, d).tolist()]}")
    print("  → i 小 = 高频（转得快，编码近距离）；i 大 = 低频（转得慢，编码远距离）")

def demo_relativity():
    section("3. 相对位置：RoPE 的灵魂恒等式")
    d, base, N = 64, 10000.0, 512
    q = torch.randn(d); k = torch.randn(d)
    th = freqs(base, d)
    cos = torch.cat([th.cos(), th.cos()]); sin = torch.cat([th.sin(), th.sin()])

    def rope(x, m):
        t = th * m
        c = torch.cat([t.cos(), t.cos()]); s = torch.cat([t.sin(), t.sin()])
        return apply_rope(x, c, s)

    ok = True
    for m, n in [(0, 7), (13, 200), (100, 100), (512, 63)]:
        lhs = rope(q, m) @ rope(k, n)                 # ⟨ρ(m)q, ρ(n)k⟩
        rhs = q @ rope(k, n - m)                      # q^T ρ(n-m) k
        err = (lhs - rhs).abs().item()
        ok &= err < 1e-4
        print(f"  m={m:>4}, n={n:>4}: ⟨ρ(m)q,ρ(n)k⟩={lhs:+.6f}  q^Tρ(n-m)k={rhs:+.6f}  Δ={err:.2e}")
    print(f"  → {'恒等式成立' if ok else '失败'}：绝对位置 m,n 的内积只通过 n-m 依赖它们")
    print("  这就是 RoPE 外推性的来源，也是它比加性位置编码强的地方")

    # 直觉：随机 q,k 的内积分布本身与 Δ 无关，真正衰减的是【相关性】
    print("\n  相对位置相关性 Corr(⟨q,k⟩, ⟨q,ρ(Δ)k⟩) = tr(ρ(Δ))/d = (2/d)·Σ_i cos(Δθ_i):")
    for delta in [0, 1, 8, 64, 256, 1024, 4096, 16384]:
        analytic = (2.0 / d) * torch.cos(th * delta).sum().item()
        emp = []
        for _ in range(400):
            a, b_ = torch.randn(d), torch.randn(d)
            emp.append((a @ b_) * (a @ rope(b_, delta)))
        emp = torch.tensor(emp).mean().item()
        print(f"    Δ={delta:>6}: 解析 = {analytic:+.4f}   经验 E[⟨q,k⟩⟨q,ρ(Δ)k⟩]/‖q‖²‖k‖² = {emp/d:+.4f}")
    print("  → 相关性随距离衰减但有振荡（低频维度周期长），这就是 RoPE 的局部性先验")

def demo_scaling():
    section("5. 长上下文外推：NTK-aware 与 YaRN")
    d = 64
    L_train, L_test = 4096, 32768
    s = L_test / L_train

    # 原始基底
    th = freqs(10000.0, d)
    # NTK-aware：放大 base（等价缩小所有 θ）→ 低频转得更慢，容纳更长距离
    base_ntk = 10000.0 * s ** (d / (d - 2))
    th_ntk = freqs(base_ntk, d)

    print(f"  外推倍数 s = {s:.0f}x   缩放后 base = {base_ntk:.0f}")
    print(f"  {'i':>3} {'θ_orig':>12} {'θ_ntk':>12} {'周期orig':>12} {'周期ntk':>12}")
    for i in [0, 1, 8, 16, 31]:
        p_orig = 2 * 3.141592653589793 / th[i].item()
        p_ntk = 2 * 3.141592653589793 / th_ntk[i].item()
        print(f"  {i:>3} {th[i].item():>12.6f} {th_ntk[i].item():>12.6f} {p_orig:>12.1f} {p_ntk:>12.1f}")

    # YaRN：分段 ramp —— 高频（短周期）不插值，低频（长周期）做线性插值
    def yarn_correction(th_i, L_train, L_test, alpha=1.0, beta=32.0):
        """YaRN 的 ramp 函数 γ(r)：r = L_train/λ，波长越短(r 越大)越不插值"""
        lam = 2 * 3.141592653589793 / th_i                     # 波长
        r = L_train / lam                                      # 训练长度内跑了几个周期
        gamma = torch.clamp((r - alpha) / (beta - alpha), 0.0, 1.0)
        return (1 - gamma) * (L_train / L_test) + gamma        # γ=1 不动，γ=0 纯插值 1/s

    lam = 2 * 3.141592653589793 / th
    corr = yarn_correction(th, L_train, L_test)
    print("\n  YaRN 插值系数（低频→接近 1/s 纯插值；高频→接近 1 不插值）:")
    for i in [0, 4, 16, 24, 31]:
        print(f"    i={i:>2}  波长={lam[i]:>12.1f}  系数={corr[i]:.4f}")
    print("  统一公式：θ'_i = θ_i · correction_i，其中 correction 是波长的分段线性函数")
    print("  直觉：高频维度在训练中已见过全部相位（周期短），不该改；低频维度没跑完一个周期，需要插值")

1. 注意力 = 数据依赖的线性算子

把一层的注意力写成矩阵形式：

$$ O = A(X)\cdot (XW_V),\qquad A(X) = \mathrm{softmax}!\left(\frac{(XW_Q)(XW_K)^\top}{\sqrt d} + M\right) $$

$A$ 是一个行随机矩阵（每行非负、和为 1），所以输出的每一行是 $V$ 各行的凸组合：

$$ o_n = \sum_{m} a_{nm} v_m,\qquad a_{nm}\ge 0,\ \sum_m a_{nm} = 1 $$

这个视角很有用：

  • 注意力 = 用输入自己生成的一个线性算子去混合 value；
  • 因为 $A$ 依赖数据，它不是"固定的卷积核"，而是动态的、内容寻址的；
  • 线性注意力（CH06）就是把这个 $A$ 换成能分解的形式。

2. 为什么要除以 $\sqrt d$

设 $q, k\in\mathbb{R}^d$ 各分量 iid $\mathcal N(0,1)$，则

$$ q^\top k = \sum_{i=1}^d q_i k_i,\qquad \mathbb{E}[q_i k_i] = 0,\quad \mathrm{Var}(q_i k_i) = \mathbb{E}[q_i^2]\mathbb{E}[k_i^2] = 1 $$

各项独立 ⇒

$$ \boxed{\mathrm{Var}(q^\top k) = d,\qquad \mathrm{std}(q^\top k) = \sqrt d} $$

ch04 第 1 节实测 $d = 16,64,128,256,1024,4096$ 全部吻合（$\mathrm{Var}\approx d$）。

后果：$d$ 越大，logits 的分布越宽，softmax 越接近 one-hot，梯度 $\partial p_i/\partial s_j = p_i(\delta_{ij}-p_j)$ 趋于 0 → 梯度饱和。

度量：稳定秩（stable rank）

$$ \mathrm{sr}(A) = \frac{\sum_i \sigma_i^2}{\sigma_{\max}^2} $$

它衡量"这个算子实际用了多少维"。实测（$d{=}512$ 的 logits 乘不同温度）：

缩放系数 稳定秩 现象
$\times 0.2$ 1.04 几乎均匀平均，输出被"抹平"
$\times 1.0$ 2.60 ——
$\times 1/\sqrt d$ —— 正常范围
$\times 3.0$ 32.13 开始尖锐
$\times 8.0$ 64.45 接近 one-hot，梯度消失

所以 $1/\sqrt d$ 是"让 logits 的尺度与 $d$ 无关"的归一化——不是玄学，是方差控制。

3. 数值稳定：平移不变性与 log-sum-exp

$$ \mathrm{softmax}(s)_i = \frac{e^{s_i}}{\sum_j e^{s_j}} = \frac{e^{s_i - m}}{\sum_j e^{s_j - m}},\quad m = \max_j s_j $$

减去最大值保证 $e^{s_i-m} \le 1$，不会溢出（$e^{89}$ 就爆 fp32，而 logits 常常到几百）。

反向传播时只需要 $\log$ 分母，用 log-sum-exp：

$$ \mathrm{LSE}(s) = m + \log\sum_j e^{s_j - m} $$

$\log\mathrm{softmax}$ 直接是 $s_i - \mathrm{LSE}(s)$，交叉熵损失也用 LSE 算，全程不产生大数。

ch04 第 2 节用 logits 很大的情形验证了手写 LSE 与 F.cross_entropy 一致。

4. 因果掩码 = 加性 $0/-\infty$ 矩阵

$$ M_{nm} = \begin{cases}0, & n \ge m\ -\infty, & n < m\end{cases} $$

加上 $M$ 后 softmax 把 $n<m$ 的项变成 0 ⇒ $A$ 变成下三角的行随机矩阵。

写成矩阵语言：

$$ A = \mathrm{softmax}(S + M) = \mathrm{softmax}\big(\mathrm{tril}(S)\big) \quad(\text{行归一化意义下}) $$

也就是"把矩阵乘限制到下三角"。这直接给出 FLOPs 减半（$2N^2d \to N^2d$ 每部分）。

实现细节：-inf 在 fp16/bf16 里参与 exp 会得到 nan（-inf - (-inf)）。 标准做法是用一个有限的大负数（如 -1e9 或 torch.finfo(dtype).min）， 或者先 masked_fill 再减 max。CH05 的 FlashAttention 里用 -inf + nan_to_num 处理初始块。

5. GQA / MQA：K/V 头的重复结构

名称 $H_q$ $H_{kv}$ KV Cache（相对 MHA）
MHA $H$ $H$ $1\times$
GQA $H$ $H/g$ $1/g$
MQA $H$ $1$ $1/H$

矩阵视角：K/V 头的重复 = 把 $(H_{kv}, D)$ 的张量沿 head 维广播 $g$ 次：

# k: (N, Hkv, D)  ->  (N, H, D)，零拷贝
k = k.unsqueeze(2).expand(N, Hkv, g, D).reshape(N, H, D)

注意 expand 是 stride=0 的视图（CH01），不占内存；但随后的 reshape 会物化。 如果想真的零拷贝进 attention kernel，需要 kernel 自己支持 g 的步长—— FlashDecoding / PagedAttention 就是这么做的。

ch04 第 4 节验证 GQA 与把 K/V 显式复制 $g$ 份的 MHA 数值一致。

6. KV Cache = 对 $K, V$ 做行追加

自回归解码第 $t$ 步：

$$ K_{1:t} = \begin{pmatrix}K_{1:t-1}\ k_t\end{pmatrix},\quad V_{1:t} = \begin{pmatrix}V_{1:t-1}\ v_t\end{pmatrix},\quad o_t = A_t\, V_{1:t} $$

即沿序列维（行）追加一行。这一步的代价：

  • 计算：$O(t\,d)$ per step（一个向量 × 矩阵），是 GEMV 而非 GEMM → 带宽受限；
  • 显存：$2\cdot H_{kv}\cdot D\cdot t\cdot (\text{layers})\cdot(\text{bytes})$

这就是为什么解码阶段瓶颈是带宽（要把整个 KV Cache 读一遍）， 而 prefill 阶段瓶颈是算力。这也是 MLA / 量化 KV / GQA 的全部动机（CH10）。

ch04 第 5 节验证"增量 decode"与"全量重算"逐步一致。

def demo_stability():
    section("2. 数值稳定：softmax 的平移不变性与 log-sum-exp")
    x = torch.tensor([1.0, 2.0, 3.0])
    print(f"  softmax(x)      = {torch.softmax(x, -1).tolist()}")
    print(f"  softmax(x+1000) = {torch.softmax(x + 1000, -1).tolist()}   ← 平移不变")

    big = torch.tensor([1000.0, 1001.0, 1002.0])
    naive = big.exp() / big.exp().sum()
    print(f"  天真实现 exp(1000+)/Σ: {naive.tolist()}   ← 上溢成 nan")
    print(f"  稳定实现（减最大值）:   {torch.softmax(big, -1).tolist()}")

    # log-sum-exp：所有对数运算的统一原语
    def lse(a, dim=-1):
        m = a.max(dim, keepdim=True).values
        return m + (a - m).exp().sum(dim, keepdim=True).log()
    a = torch.randn(4, 100) * 20
    check("log Σ exp(a) == max + log Σ exp(a-max)", a.logsumexp(-1), lse(a).squeeze(-1))
    check("softmax 对数 == a - logsumexp(a)", torch.log_softmax(a, -1), a - a.logsumexp(-1, keepdim=True))
    print("  → 交叉熵损失 = logsumexp(logits) - logits[target]，天然数值稳定")
    print("  → 同样的 '减最大值' 技巧会在 CH05 里变成【在线 softmax】，是 FlashAttention 的数学核心")

def mha(q, k, v, causal=False, scale=None):
    """标准多头注意力: q,k,v: (B,H,N,D)"""
    d = q.shape[-1]
    s = torch.einsum("bhnd,bhmd->bhnm", q, k) * (scale or d ** -0.5)
    if causal:
        n = q.shape[2]
        s = s.masked_fill(torch.triu(torch.ones(n, n, dtype=torch.bool), 1), float("-inf"))
    return torch.einsum("bhnm,bhmd->bhnd", torch.softmax(s, -1), v)

1. 要解决的问题

朴素注意力需要物化 $N\times N$ 的分数矩阵：

步骤 显存 HBM 访问
$S = QK^\top$ $N^2$ 读 $Q,K$，写 $S$
$P = \mathrm{softmax}(S)$ $N^2$ 读 $S$，写 $P$
$O = PV$ $N$ 读 $P,V$，写 $O$

$N{=}8192$ 时 $N^2$ 个 fp32 = 268 MB（一层一头就这么多，实际还要乘 $B\cdot H$）。 显存是 $O(N^2)$，HBM 访问也是 $O(N^2)$ —— 而且这些都是 CH01 说的"带宽受限"操作。

FlashAttention 的两个武器：

  1. 在线 softmax：不存 $S$、$P$，用递推维护 $(m, \ell, O)$；
  2. 分块（tiling）：$Q$ 分块外层循环、$K,V$ 分块内层循环，中间块只活在 SRAM。

2. 在线 softmax 的推导

目标：流式地算 $O = \frac{\sum_j e^{s_j} v_j}{\sum_j e^{s_j}}$，每次只看到一块 $s$。

维护三个量：

  • $m$：到目前为止见过的行最大值
  • $\ell$：到目前为止的（按当前 $m$ 归一化的）分母和
  • $O$：到目前为止的（按当前 $m$ 归一化的）分子加权和

看到新块 $S$ 时：

$$ \begin{aligned} m_{new} &= \max(m_{old},\ \mathrm{rowmax}(S))\ \ell_{new} &= \ell_{old}\cdot e^{\,m_{old}-m_{new}} + \mathrm{rowsum}\big(e^{\,S-m_{new}}\big)\ O_{new} &= O_{old}\cdot e^{\,m_{old}-m_{new}} + e^{\,S-m_{new}} V \end{aligned} $$

最后 $O_{final} = O / \ell$。

正确性来自两件事：

  1. softmax 的平移不变性（CH02 §3.3）：分母分子同时乘 $e^{-m}$ 不变；
  2. 指数的可分解性：$e^{s - m_{new}} = e^{s - m_{old}} \cdot e^{m_{old} - m_{new}}$， 所以旧贡献只要乘一个标量重缩放因子就能对齐到新的 $m$。

于是"重缩放"就是：$O_{old}$ 和 $\ell_{old}$ 都乘同一个 $e^{m_{old}-m_{new}}$。

这正是 CH07 Gated DeltaNet 里"块间状态传递"的同款技巧， 也是 CH11 Ring Attention 跨设备累加的同款技巧。学会一次，用三处。

3. 两级分块

for i in range(0, N, bq):          # Q 块（外层）—— 结果写回 HBM
    load Q[i:i+bq]
    for j in range(0, N, bk):      # K,V 块（内层）—— 只活在 SRAM
        load K[j:j+bk], V[j:j+bk]
        S = Q_i K_j^T              # (bq, bk)
        online softmax update
    write O_i / ell_i

因果模式下：内层只扫到 $j \le i$（省一半 FLOPs），且完全跳过的块不算。

5. IO 复杂度的账

设 SRAM = $M$。分块大小受限于 $b\,d \lesssim M$。

  • 朴素实现 HBM 访问：$\Theta(Nd + N^2 + N^2 + Nd) = \Theta(N^2)$
  • FlashAttention：$\Theta!\left(\frac{N^2 d^2}{M}\right)$

实测（$N{=}8192, d{=}128$，$M$ 按 100 KB 估）：

注意：FLOPs 完全没变（甚至因为要重算，反向更多）。省的全是访存。

6. 反向传播：用重算换显存

前向只保存：

  • 输出 $O$：$O(Nd)$
  • logsumexp $L$：$O(N)$

反向时重算 $S$、$P$（在 SRAM 内），代价是多一次 $O(N^2d)$ 的 GEMM， 但换来的是显存从 $O(N^2)$ 降到 $O(N)$。

$$ \frac{\partial L}{\partial S} = P \odot \big(dO\, V^\top - \mathrm{rowsum}(dO \odot O)\big) $$

（这个式子是标准的 softmax 反向 + $O$ 的行内积修正项。）

q = tl.load(Q_block)                      # (BLOCK_M, HEAD_DIM)

def demo_online_softmax():
    section("1. 在线 softmax：把 softmax 改成可流式的递推")
    x = torch.randn(4, 10) * 8                       # 假装是一行 logits 被切成若干块

    ref = torch.softmax(x, -1)

    # 逐块（每块 3 个元素）流式更新
    m = torch.full((4, 1), NEG)
    l = torch.zeros(4, 1)
    o = torch.zeros(4, 10)                            # 这里 o 存的是未归一化的加权和（输入用 one-hot）

# -------------------------------------------------- 2. 分块 FlashAttention
def flash_attention(Q, K, V, bq=64, bk=64, causal=False, scale=None):
    """两级分块：外层切 Q，内层切 K/V。中间块只有 bq×bk，永不落 HBM。
    Q,K,V: (N, d) 单头；返回 (N, d)
    """
    N, d = Q.shape
    s = scale if scale is not None else d ** -0.5
    O = torch.zeros(N, d)
    L = torch.zeros(N, 1)                              # 只额外存 O(N) 的 logsumexp，反向要用
    for i in range(0, N, bq):
        hi = min(i + bq, N)
        Qi = Q[i:hi]
        Oi = torch.zeros(hi - i, d)
        mi = torch.full((hi - i, 1), NEG)
        li = torch.zeros(hi - i, 1)
        j_end = (i + bq) if causal else N               # 因果：只看自己及之前
        for j in range(0, j_end, bk):
            hj = min(j + bk, N)
            Sij = (Qi @ K[j:hj].T) * s                  # (bq, bk) —— 只活在 SRAM
            if causal and hj > i:                       # 对角块内还要屏蔽"未来"
                rows = torch.arange(i, hi)[:, None]
                cols = torch.arange(j, hj)[None, :]
                Sij = Sij.masked_fill(cols > rows, NEG)
            m_new = torch.maximum(mi, Sij.max(-1, keepdim=True).values)
            corr = torch.nan_to_num(torch.exp(mi - m_new), nan=0.0)
            P = torch.exp(Sij - m_new)
            li = li * corr + P.sum(-1, keepdim=True)
            Oi = Oi * corr + P @ V[j:hj]
            mi = m_new
        O[i:hi] = Oi / li
        L[i:hi] = mi + li.log()                          # 保存 logsumexp 供反向使用
    return O, L


def naive_attention(Q, K, V, causal=False, scale=None):
    N, d = Q.shape
    s = scale if scale is not None else d ** -0.5
    S = (Q @ K.T) * s
    if causal:
        S = S.masked_fill(torch.triu(torch.ones(N, N, dtype=torch.bool), 1), NEG)
    P = torch.softmax(S, -1)
    return P @ V, S.logsumexp(-1, keepdim=True)

CH06

线性注意力

代码：code/ch06_linear_attention.py 前置：CH02（结合律）、CH05（分块/在线 softmax）

1. 去掉 softmax，结合律就回来了

CH02 说过：$(QK^\top)V$ 是 $O(N^2d)$，而 $Q(K^\top V)$ 是 $O(Nd^2)$ —— 但因为 softmax 卡在中间，两者不等价。

如果去掉 softmax（只保留因果掩码）：

$$ o_t = \sum_{j\le t} (q_t^\top k_j)\, v_j = \underbrace{\Big(\sum_{j\le t} v_j k_j^\top\Big)}_{S_t}\, q_t $$

定义状态矩阵 $S_t \in \mathbb{R}^{d_v\times d_k}$：

$$ \boxed{S_t = \sum_{j\le t} v_j k_j^\top = S_{t-1} + v_t k_t^\top} $$

它有两个名字，理解它要同时用这两个名字：

视角 说法 einsum
外积累加 每步加一个秩1矩阵 $v_t k_t^\top$ bnk,bnv->bkv
联想记忆 $S$ 是 key→value 的线性联想记忆 $S k \approx v$

复杂度：

训练（$N$ 个 token 一起） 解码（单步）
softmax attention $O(N^2 d)$ $O(Nd)$（要扫全 KV）
线性注意力 $O(N d^2)$ $O(d^2)$（常数）

当 $N \gg d$ 时线性注意力完胜；解码更是从"每步读整个 KV Cache"变成"更新一个 $d\times d$ 矩阵"。

2. 加入衰减：遗忘 = 谱收缩

$$ S_t = \lambda\, S_{t-1} + v_t k_t^\top,\qquad 0<\lambda\le 1 $$

展开：$S_t = \sum_{j\le t} \lambda^{\,t-j}\, v_j k_j^\top$ —— 越老的记忆权重越小。

谱视角：乘 $\lambda$ 是对 $S$ 的所有奇异值做均匀收缩：$\sigma_i \to \lambda \sigma_i$。 所以 $\lambda$ 是"遗忘率"：$\lambda$ 越小，旧记忆衰减越快。

稳态下 $S$ 的有效记忆长度约 $1/(1-\lambda)$。

3. Chunkwise 并行（训练时怎么上 GPU）

纯递推 $S_t = \lambda S_{t-1} + v_t k_t^\top$ 是串行的，没法并行——训练时不能这么算。 解决办法是分块：

把序列切成 $C$ 个长度为 $c$ 的块。对块 $[l]$：

$$ O^{[l]} = \underbrace{Q^{[l]} K^{[l]\top} \odot M}{\text{块内：二次，可并行}} V^{[l]} \;+\; \underbrace{Q^{[l]}\,(\text{块间状态})} $$}

块间状态递推（块级别）：

$$ S^{[l+1]} = \lambda^{c}\, S^{[l]} + \sum_{j\in\text{block }l} \lambda^{\,c-1-\mathrm{idx}(j)}\, v_j k_j^\top $$

代码要点（这是 ch06 里最容易写错的地方）：

# 块内系数：块内第 idx 个 token，出块时还剩下 c-1-idx 次衰减
coeff = lam ** (c - 1 - idx[:c].float())
S = (lam ** c) * S + (Vc * coeff[:, None]).T @ Kc

对比 CH05：FlashAttention 是"块内二次 + 无块间状态"（因为 softmax 的归一化是全局的， 用 $m/\ell$ 递推）；线性注意力是"块内二次 + 块间状态传递"。 CH07 的 Gated DeltaNet 会把两者都用上。

复杂度：块内 $O(C c^2 d)$，块间 $O(C d^2)$，总 $O(N c d + N d^2/c)$， 取 $c \approx \sqrt{N}$ 最优。

4. 核特征映射：用特征逼近 softmax

如果还想要 softmax 的"尖锐"性质，可以用核技巧：

$$ \mathrm{softmax}(q^\top k) \approx \phi(q)^\top \phi(k) $$

于是 $\mathrm{softmax}(QK^\top)V \approx \phi(Q)\big(\phi(K)^\top V\big)$，结合律又成立了。

ReLU 特征（最简单）

$$ \phi(x) = \mathrm{ReLU}(x)\quad \text{（或 } \mathrm{ReLU}(x)^2 \text{，对应二阶核）} $$

FAVOR+（Performer）

$$ \phi(x) = \frac{e^{\lVert x\rVert^2/2}}{\sqrt{D}}\sqrt{2}\,\big(\cos(xW + b)\big),\qquad W_{ij}\sim \mathcal N(0,1),\ b_i\sim U(0,2\pi) $$

这是 Random Fourier Features 对 RBF 核的无偏估计：

$$ \mathbb{E}\big[\phi(q)^\top\phi(k)\big] = e^{q^\top k} \cdot e^{-\lVert q\rVert^2/2 - \lVert k\rVert^2/2} $$

ch06 第 4 节实测（归一化输入后，温度 $T{=}2$）：

特征维 $D$ 相对误差
64 1.1513
256 0.3874
1024 0.2013
4096 0.0975

误差随 $D$ 单调下降但收敛慢（$O(1/\sqrt D)$），这就是 Performer 类方法在实践中 不如 softmax attention 的主要原因之一。

写代码时踩过的坑：公式里 $e^{\lVert x\rVert^2/2}$ 和 $\sqrt{2/D}$ 的位置和符号很容易搞错， 一旦错，误差会是几百倍而不是 1 倍量级。

5. 线性注意力的失败模式：秩饱和 / 记忆冲突

状态 $S_t = \sum_{j\le t} v_j k_j^\top$ 的秩最多是 $t$（每步 +1），但维度只有 $d\times d$。

$$ \mathrm{rank}(S_t) \le \min(t,\ d) $$

当 $t > d$ 后，新写入的 $v_t k_t^\top$ 无法再张成新的方向，只能与已有记忆"挤在一起"：

$$ S k_t \approx \underbrace{v_t}{\text{想要的}} + \underbrace{\sum $$}(v_j k_j^\top k_t)}_{\text{干扰（记忆冲突）}

读出的值混入了其它 key 的记忆 → 召回精度崩塌。这就是纯线性注意力在长上下文上 不如 softmax attention 的根本原因（复制/联想任务上尤其明显）。

Δ rule 预览

解决办法：写入前先擦除与该 key 关联的旧值（Widrow-Hoff / delta rule）：

$$ S_t = S_{t-1} + \beta_t\big(v_t - S_{t-1}k_t\big) k_t^\top $$

def demo_outer_product_state():

def demo_decay():
    section("2. 指数衰减 = 遗忘门 = 状态的谱收缩")
    d, N = 16, 64
    K, V, Q = torch.randn(N, d), torch.randn(N, d), torch.randn(N, d)
    lam = 0.95

    S = torch.zeros(d, d)
    O_rec = []
    for t in range(N):

        O_rec.append(S @ Q[t])
    O_rec = torch.stack(O_rec)

    idx = torch.arange(N)

    print("  数学上 S ← λS 是对状态做谱缩放：σ_i(S) → λ·σ_i(S)，所有奇异值等比收缩")

# ------------------------------------------------- 3. chunkwise 并行训练
def linear_attn_chunkwise(Q, K, V, lam=0.95, chunk=16):
    """chunkwise 线性注意力：块内用二次形式（可并行），块间只传状态矩阵。
    Q,K,V: (N, d) 单头。返回 (N, d)
    """
    N, d = Q.shape
    O = torch.zeros(N, d)
    S = torch.zeros(d, d)                                  # 跨 chunk 的状态
    idx = torch.arange(chunk)
    # 块内相对衰减矩阵：Δ[t,j] = λ^{t-j} for j ≤ t
    dec = torch.where(idx[:, None] >= idx[None, :],
                      lam ** (idx[:, None] - idx[None, :]).float(), 0.0)
    # 块内从状态衰减到每个位置的系数
    a_rel = lam ** (idx.float() + 1)                        # 位置 t 相对块起点的累积衰减 λ^{t+1}

    for c in range(0, N, chunk):
        h = min(chunk, N - c)
        Qc, Kc, Vc = Q[c:c + h], K[c:c + h], V[c:c + h]
        d_ = dec[:h, :h]
        # ① 块内（intra）：二次注意力形式，O(chunk² d)，全部并行
        intra = ((Qc @ Kc.T) * d_) @ Vc
        # ② 块间（inter）：状态与 query 的一次矩阵乘，O(chunk·d²)，乘上块内累积衰减
        inter = (Qc @ S.T) * a_rel[:h, None]                 # (h,d_v) ← λ^{t+1}·(S q_t)
        O[c:c + h] = intra + inter
        # ③ 推进状态到块末：S_{h-1} = λ^h S_start + Σ_j λ^{h-1-j} v_j k_jᵀ
        coeff = lam ** (h - 1 - idx[:h].float())             # [λ^{h-1}, ..., λ^0]
        S = (lam ** h) * S + (Vc * coeff[:, None]).T @ Kc
    return O

def demo_kernel_features():
    section("4. 核技巧：用 φ(q)·φ(k) 逼近 softmax")
    N, d, D = 128, 64, 256          # D = 随机特征维数
    Q, K, V = torch.randn(N, d), torch.randn(N, d), torch.randn(N, d)

    def softmax_attn(Q, K, V):
        return torch.softmax(Q @ K.T / d ** 0.5, -1) @ V

    def relu_feature(x):
        return F.relu(x) + 1.0       # 保证非负

    def random_feature(x, D, seed=0):
        """FAVOR+（三角随机特征）：
        φ(x)_i = e^{‖x‖²/2} · √(2/D) · cos(w_iᵀx + b_i),  w_i~N(0,I), b_i~U(0,2π)
        则 E[φ(x)·φ(y)] = e^{‖x‖²/2+‖y‖²/2} · e^{-‖x-y‖²/2} = e^{xᵀy}
        """
        g = torch.Generator().manual_seed(seed)
        W = torch.randn(d, D, generator=g)
        b = torch.rand(D, generator=g) * 2 * 3.141592653589793
        return torch.exp((x ** 2).sum(-1, keepdim=True) / 2) * (2.0 / D) ** 0.5 * torch.cos(x @ W + b)

    def kernel_attn(qf, kf, V):
        """φ(Q)φ(K)ᵀV / φ(Q)φ(K)ᵀ1 —— 分母是核版的行归一化"""
        S = qf @ kf.T
        return (S @ V) / S.sum(-1, keepdim=True)

    # 为公平对比，把 q,k 归一化到单位球，用温度 T 控制 logits 尺度
    # 目标核：exp(T·q̂ᵀk̂)，即 x=√T q̂, y=√T k̂ 时近似 exp(xᵀy)
    T = 2.0
    Qn = Q / Q.norm(dim=-1, keepdim=True)
    Kn = K / K.norm(dim=-1, keepdim=True)
    o_soft = torch.softmax(T * (Qn @ Kn.T), -1) @ V

    x, y = (T ** 0.5) * Qn, (T ** 0.5) * Kn
    print(f"  归一化输入 + 温度 T={T}：与 softmax 注意力的相对误差")
    qf, kf = relu_feature(x), relu_feature(y)
    err = ((kernel_attn(qf, kf, V) - o_soft).norm() / o_soft.norm()).item()
    print(f"    {'ReLU 特征(φ=relu+1)':<28s} {err:.4f}")
    for D_ in [64, 256, 1024, 4096, 16384]:
        o_rf = kernel_attn(random_feature(x, D_), random_feature(y, D_), V)
        err = ((o_rf - o_soft).norm() / o_soft.norm()).item()
        print(f"    {'随机特征 FAVOR+(D=%d)' % D_:<28s} {err:.4f}")
    print("  注意：φ(x)·φ(y) 的方差 ∝ e^{‖x‖²+‖y‖²}，输入范数越大需要的特征维数越多。")
    print("  真实大模型 logits 尺度更宽（‖q‖²≈d），这正是 Performer 落地困难的原因之一。")
    print("  核技巧把 softmax 的 exp(q·k) 拆成 φ(q)·φ(k)，从而可以用结合律")
    print("  代价：需要 D ≫ d 才能逼近好，且非负性约束让表达力受限 → 后续工作转向直接用状态矩阵")

def demo_memory_conflict():

    d = 32
    torch.manual_seed(1)
    # 构造 d/2 个"应记住的 key-value 对"，然后看能否正确读出

        Kmem = torch.randn(n_pairs, dk); Kmem = Kmem / Kmem.norm(dim=-1, keepdim=True)

        for j in range(n_pairs):
            S += torch.outer(Vmem[j], Kmem[j])
        # 回读：q = k_j
        errs = []
        for j in range(n_pairs):
            got = S @ Kmem[j]
            errs.append((got - Vmem[j]).norm().item() / Vmem[j].norm().item())

        print(f"  记忆 {n_pairs:>3} 对: 状态秩 = {rank:>3}/{d}   平均回读相对误差 = {sum(errs)/len(errs):.3f}")

    print("  → 解决思路①：增大 d（贵）  ②：加衰减（忘掉旧的）  ③：delta rule 主动擦除（CH07）")

    # DeltaNet 的 Δ rule 预览：n_pairs=32（已满秩）时对比，并展示多遍收敛
    print("\n  Δ rule 预览（n_pairs=32，状态已无空余秩）:")
    n_pairs = 32
    Kmem = torch.randn(n_pairs, d); Kmem = Kmem / Kmem.norm(dim=-1, keepdim=True)
    Vmem = torch.randn(n_pairs, d)
    S_lin = sum(torch.outer(Vmem[j], Kmem[j]) for j in range(n_pairs))
    lin_err = sum(((S_lin @ Kmem[j] - Vmem[j]).norm() / Vmem[j].norm()).item()
                  for j in range(n_pairs)) / n_pairs
    print(f"    线性累加（1 遍）                 : 回读相对误差 = {lin_err:.4f}")
    S = torch.zeros(d, d)
    for epoch in range(1, 9):
        for j in range(n_pairs):                              # Δ rule：先读、算误差、再修正
            S = S + torch.outer(Vmem[j] - S @ Kmem[j], Kmem[j]) / (Kmem[j] @ Kmem[j])
        if epoch in (1, 2, 4, 8):
            err = sum(((S @ Kmem[j] - Vmem[j]).norm() / Vmem[j].norm()).item()
                      for j in range(n_pairs)) / n_pairs
            print(f"    Δ rule（{epoch} 遍）               : 回读相对误差 = {err:.4f}")
    print("  → S ← S + (v - Sk)kᵀ/‖k‖²  = 先读出旧值、算残差、沿 k 方向修正（Widrow-Hoff / LMS）")
    print("  → 它【主动擦除】k 方向上已存的内容，因此不会被秩饱和拖垮 → 详见 CH07")

Gated DeltaNet

代码：code/ch07_gated_deltanet.py 前置：CH05（在线 softmax / 分块）、CH06（外积状态 / chunkwise） ⚠️ 这是本教程数学密度最高的一章，建议先跑一遍代码再回来读推导。

1. 递推式与它的直觉

Gated Delta Rule：

$$ \boxed{S_t = \alpha_t\, S_{t-1}\big(I - \beta_t k_t k_t^\top\big) + \beta_t\, v_t k_t^\top} $$

等价写法（更直观）：

$$ S_t = \alpha_t S_{t-1} + \beta_t\big(v_t - \alpha_t S_{t-1}k_t\big)k_t^\top $$

读法（三步）：

  1. 读出：$\hat v_t = \alpha_t S_{t-1} k_t$ —— 当前状态认为 $k_t$ 对应什么值；
  2. 残差：$v_t - \hat v_t$ —— 新值和旧记忆的差；
  3. 写入：沿 $k_t$ 方向做秩1更新，把残差写进去。

这就是 Widrow-Hoff / LMS 的 delta rule，也等价于在线最小二乘（RLS）的一步： $S$ 始终在拟合"最近的 $(k, v)$ 配对"。

与 CH06 纯外积累加的区别：

纯线性注意力 Gated DeltaNet
写入 $S \mathrel{+}= v k^\top$（只加） 先擦除 $Sk^\top$ 方向，再加残差
转移矩阵 $I$（恒等） $\alpha_t(I - \beta_t k_t k_t^\top)$
秩饱和 严重（CH06 §5） 被擦除缓解

2. $I - \beta kk^\top$ 的谱结构

设 $\lVert k\rVert = 1$，$T = I - \beta kk^\top$。它在 $k$ 方向和正交补上的作用完全不同：

$$ T k = (1-\beta\lVert k\rVert^2) k,\qquad T u = u \ \ (\forall u \perp k) $$

所以特征值：${1-\beta}$（1 个）和 ${1}$（$d-1$ 个）。取不同 $\beta$：

$\beta$ 矩阵性质 验证
$0.5$ 收缩：沿 $k$ 方向压到 0.5 ——
$1.0$ 正交投影 $P$：$k$ 方向清零 $P^2 = P$（幂等）
$2.0$ Householder 反射 $H$：$k$ 方向取反 $H^\top H = I,\ H^2 = I$（正交对合）

Gated DeltaNet 用 $\beta \in (0,1)$ ⇒ 沿 $k$ 方向部分擦除，其余 $d-1$ 个方向完全不动。

这句话很重要：擦除是各向异性的。 对比 Mamba2 / 状态空间对偶（SSD）的 $S_t = \alpha_t S_{t-1} + \beta_t v_t k_t^\top$， 那里的衰减 $\alpha_t I$ 是各向同性的（所有方向一起缩）。 Gated DeltaNet 的 $\alpha_t(I - \beta_t k_t k_t^\top)$ 只在 $k_t$ 这一个方向上额外收缩。 这让它可以"精确删除某条记忆"而不误伤其它记忆 —— 这正是联想召回任务需要的。

3. 为什么串行递推上不了 GPU

$S_t$ 依赖 $S_{t-1}$，$N$ 步完全串行。GPU 上这意味着 $N$ 次 kernel launch， 每次只做一个 $d\times d$ 的外积更新 —— 算术强度极低，完全跑不起来。

必须 chunkwise：块内用矩阵运算并行，块间只做 $N/c$ 步状态传递。 难点在于：块内第 $t$ 个输出依赖块内所有前面的转移矩阵的乘积：

$$ S_t = \Big(\prod_{i\le t} \alpha_i\big(I-\beta_i k_i k_i^\top\big)\Big) S_0 + \cdots $$

那个 $\prod_{i\le t}(I - \beta_i k_i k_i^\top)$ 是 $t$ 个 $d\times d$ 矩阵相乘 —— 必须压缩。

4. WY 表示：把一串秩1修正压成一个 $d\times C$ 矩阵

这是从 Householder QR 的分块化（Bischof–Van Loan，LAPACK 的紧凑 WY 表示）搬过来的技巧。

定理：对任意 ${(k_i,\beta_i)}_{i\le t}$，存在 $W \in \mathbb{R}^{d\times (t+1)}$ 使得

$$ \prod_{i\le t}\big(I - \beta_i k_i k_i^\top\big) = I - W_{0:t}\, K_{0:t}^\top $$

其中 $W_{0:t}$ 的列 $w_i$ 满足下三角递推：

$$ w_t = \beta_t\Big(k_t - \sum_{i<t}(k_i^\top k_t)\, w_i\Big) $$

写成矩阵就是一个下三角线性系统（记 Gram 矩阵 $G_{ij} = k_i^\top k_j$）：

$$ \big(I + \mathrm{diag}(\beta)\cdot \mathrm{tril}(G, -1)\big)\, W = \mathrm{diag}(\beta)\, K $$

用 torch.linalg.solve_triangular(..., upper=False) 一次解出全部 $W$。

收益：

直接累乘 WY 表示
运算 $C$ 次 $d\times d$ 矩阵乘，$O(Cd^2)$，串行 一次 $C\times C$ 三角求解，可 batched
并行度 无（严格串行） 沿 batch / head 完全并行

ch07 第 2 节对 $t = 0..4$ 逐个验证了 $\prod_{i\le t}(I - \beta_i k_ik_i^\top) = I - W_{0:t}K_{0:t}^\top$。

5. 加上门控 $\alpha_t$：累积衰减归一化

带 $\alpha_t$ 时，先做累积衰减：

$$ c_t = \prod_{i\le t}\alpha_i,\qquad \beta'_t = \frac{\beta_t}{c_t} $$

这样可以把 $\alpha$ 从递推里"除掉"，剩下的结构与 §4 完全一样（只是 $\beta$ 换成 $\beta'$）。 块内最后再乘回 $c_t$。

6. 完整的 chunkwise 算法

设块长 $C$，块起始状态 $S_0$。

Step 1（并行）：Gram 矩阵 $G = K K^\top \in \mathbb{R}^{C\times C}$

Step 2（并行，三角求解）：

$$ \big(I + \mathrm{diag}(\beta)\mathrm{tril}(G,-1)\big)W = \mathrm{diag}(\beta)K \tag{求 $W$} $$

$$ \big(I + \mathrm{tril}(G,-1)\mathrm{diag}(\beta)\big)X = \mathrm{tril}(G,-1)\mathrm{diag}(\beta')V \tag{求 $X$} $$

Step 3（并行）：写入项

$$ D = \mathrm{diag}(\beta')V - \mathrm{diag}(\beta) X $$

Step 4（块内输出）：令 $M = \mathrm{tril}(QK^\top)$（因果掩码，索引 $[t,j] = q_t^\top k_j$，保留 $j\le t$）

$$ O_{\text{block}} = \mathrm{diag}(c)\Big(\underbrace{Q S_0^\top - M\,(W S_0^\top)}{\text{块间}} \;+\; \underbrace{M\, D}\Big) $$}

Step 5（推进状态）：

$$ S \leftarrow c_{C-1}\Big(S - (WS_0^\top)^\top K + D^\top K\Big) $$

⚠️ 本教程踩的最大的坑：Step 4 的 $M$ 必须是 $\mathrm{tril}(Q K^\top)$（索引 $[t,j]$）， 不能写成 $\mathrm{tril}(K Q^\top)$ 再转置——虽然看起来"转置一下就行"， 但 tril 的方向在转置后是反的，会导致 max|Δ| ~ 4e+03。 写这类代码时，把每个矩阵的索引含义写进注释：[t,j] = 第 t 个 query 对第 j 个 key。

"""
CH07 Gated DeltaNet：Δ rule、Householder 变换、WY 表示与 chunkwise 并行

这是本教程数学密度最高的一章。核心递推（Gated Delta Rule）：

    S_t = α_t · S_{t-1} · (I - β_t k_t k_tᵀ) + β_t v_t k_tᵀ
        = α_t S_{t-1} + β_t (v_t - α_t S_{t-1} k_t) k_tᵀ          （等价写法）

读法：
  · 先"读出"当前 key 关联的值：v̂ = α_t S_{t-1} k_t
  · 算残差：v_t - v̂
  · 沿 k_t 方向写入残差（秩1更新）
  这就是 Widrow-Hoff / LMS 的 delta rule，等价于在线最小二乘（RLS）的一步。

学习目标
  1. I - βkkᵀ 的谱结构：投影 / Householder 反射 / 收缩 —— 三种特例
  2. 为什么"擦除"能突破 CH06 的秩饱和
  3. chunkwise 并行：把 Σ_t 的转移矩阵 Π(I-βkkᵀ) 用【WY 表示】压缩
  4. 序列递推 → 三角线性系统求解（UT transform 的本质），这是能上 GPU 的关键
  5. 与 Mamba2 / SSD 的矩阵视角对比
"""

# ============================================================ 参考实现
def gdn_naive(Q, K, V, beta, alpha):
    """逐 token 循环（慢，但最易读）—— 作为正确性基准。
    Q,K,V: (B, N, d)   beta, alpha: (B, N)   S: (B, d, d)
    """
    B, N, d = Q.shape
    S = torch.zeros(B, d, d)
    outs = []
    for t in range(N):
        kt = K[:, t:t + 1]                                   # (B,1,d)
        a = alpha[:, t].view(B, 1, 1)
        b = beta[:, t].view(B, 1, 1)
        v_hat = a * torch.bmm(S, kt.transpose(1, 2)).transpose(1, 2)   # α_t · S k_t
        delta = V[:, t:t + 1] - v_hat                        # 残差
        S = a * S + b * torch.bmm(delta.transpose(1, 2), kt)  # 秩1更新 (d,1)@(1,d)
        outs.append(torch.bmm(S, Q[:, t:t + 1].transpose(1, 2)).transpose(1, 2))
    return torch.cat(outs, dim=1)


# ============================================================ chunkwise
def gdn_chunkwise(Q, K, V, beta, alpha, chunk=32):
    """chunkwise 并行版：块内全部用矩阵运算（无 token 循环），块间传递状态 S。

    块内推导（块起点状态记为 S₀，块内索引 t=0..C-1）
      ① 归一化衰减：c_t = Π_{i≤t} α_i，令 S_t = c_t·(S₀A_t + Z_t) 可把递推化为无衰减形式
         ⇒ 只需把写入项的 β 换成 β'_t = β_t / c_t
      ② 转移矩阵 A_t = Π_{i≤t}(I - β_i k_i k_iᵀ) 用 WY 表示：A_t = I - W_{0:t} K_{0:t}ᵀ
         W 由三角系统 (I + diag(β)·tril(G,-1)) W = diag(β)·K 解出，G = K Kᵀ
      ③ Z_t 的递推里出现 X_t = Z_{t-1}k_t，同样构成三角系统：
         (I + tril(G,-1)·diag(β)) X = tril(G,-1)·diag(β')·V，然后 D_t = β'_t v_t - β_t X_t
      ④ 输出：o_t = c_t·[ S₀q_t - Σ_{i≤t}(S₀w_i)(k_iᵀq_t) + Σ_{j≤t} D_j (k_jᵀq_t) ]
      ⑤ 块末状态：S_end = c_{C-1}·( S₀ - (W S₀ᵀ)ᵀ Kᵀ + Dᵀ K )
    """
    B, N, d = Q.shape
    assert N % chunk == 0, "N 必须是 chunk 的整数倍（实际实现会做 padding）"
    Nc = N // chunk
    Qc = Q.view(B, Nc, chunk, d)
    Kc = K.view(B, Nc, chunk, d)
    Vc = V.view(B, Nc, chunk, d)
    bc = beta.view(B, Nc, chunk)
    ac = alpha.view(B, Nc, chunk)

    c = torch.cumprod(ac, dim=-1)                       # 块内累积衰减 c_t
    bp = bc / c                                         # β'_t = β_t / c_t

    G = torch.matmul(Kc, Kc.transpose(-1, -2))          # (B,Nc,C,C) Gram 矩阵
    L1 = torch.tril(torch.ones(chunk, chunk), -1)       # 严格下三角
    Gt = G * L1                                         # tril(G, -1)

    # ② WY 表示：解 (I + diag(β)·tril(G,-1)) W = diag(β)·K
    A1 = torch.eye(chunk) + bc.unsqueeze(-1) * Gt       # [t,j] = δ_tj + β_t·G[t,j]
    W = torch.linalg.solve_triangular(A1.reshape(-1, chunk, chunk),
                                      (bc.unsqueeze(-1) * Kc).reshape(-1, chunk, d),
                                      upper=False).view(B, Nc, chunk, d)
    # ③ X 的三角系统：(I + tril(G,-1)·diag(β)) X = tril(G,-1)·diag(β')·V
    A2 = torch.eye(chunk) + Gt * bc.unsqueeze(-2)       # [t,j] = δ_tj + G[t,j]·β_j
    rhs2 = torch.matmul(Gt * bp.unsqueeze(-2), Vc)
    X = torch.linalg.solve_triangular(A2.reshape(-1, chunk, chunk),
                                      rhs2.reshape(-1, chunk, d),
                                      upper=False).view(B, Nc, chunk, d)
    D = bp.unsqueeze(-1) * Vc - bc.unsqueeze(-1) * X    # 写入项 (B,Nc,C,d)

    # ④ 输出所需的因果 mask：[t,j] = q_tᵀk_j，只保留 j ≤ t（key 在 query 之前）
    MmT = torch.matmul(Qc, Kc.transpose(-1, -2)) * torch.tril(torch.ones(chunk, chunk))

    O = torch.zeros_like(Qc)
    S = torch.zeros(B, d, d)
    for ci in range(Nc):                                 # 块间：只有 Nc 步串行
        WS = torch.matmul(W[:, ci], S.transpose(-1, -2))         # (B,C,d) = W·S₀ᵀ
        QS = torch.matmul(Qc[:, ci], S.transpose(-1, -2))        # (B,C,d) = Q·S₀ᵀ
        inter = QS - torch.matmul(MmT[:, ci], WS)                # S₀ 经转移矩阵后的贡献
        intra = torch.matmul(MmT[:, ci], D[:, ci])               # 块内新写入的贡献
        O[:, ci] = c[:, ci].unsqueeze(-1) * (inter + intra)
        # ⑤ 推进状态
        S = c[:, ci, -1].view(B, 1, 1) * (
            S - torch.matmul(WS.transpose(-1, -2), Kc[:, ci])    # -(W S₀ᵀ)ᵀ Kᵀ
              + torch.matmul(D[:, ci].transpose(-1, -2), Kc[:, ci]))  # + Dᵀ K
    return O.view(B, N, d)

def demo_householder():
    section("1. I - βkkᵀ 的谱结构：投影 / 反射 / 收缩")
    d = 8
    k = torch.randn(d); k = k / k.norm()
    I = torch.eye(d)
    Kn = k / k.norm()

    print("  取 ‖k‖=1，考察 T = I - β k kᵀ，作用在 k 方向上：T k = (1-β‖k‖²)k")
    for name, beta_val in [("β‖k‖²=0.5  收缩", 0.5),
                           ("β‖k‖²=1    正交投影", 1.0),
                           ("β‖k‖²=2    Householder 反射", 2.0)]:
        T = I - beta_val * torch.outer(Kn, Kn)
        eig = torch.linalg.eigvalsh(T)
        print(f"  {name:<28s} 特征值: {[f'{e:.2f}' for e in eig.sort().values.tolist()]}")
        if abs(beta_val - 1.0) < 1e-9:
            check("  P² = P（幂等 ⇒ 投影矩阵）", T @ T, T, atol=1e-5)
        if abs(beta_val - 2.0) < 1e-9:
            check("  HᵀH = I 且 H² = I（正交对合 ⇒ Householder）", T.T @ T, I, atol=1e-5)
            check("  H² = I", T @ T, I, atol=1e-5)
    print("  → Gated DeltaNet 用 β∈(0,1) 且 k 归一化 ⇒ 特征值 1-β ∈ (0,1)：沿 k 方向【收缩/擦除】")
    print("    其余 d-1 个正交方向特征值恒为 1：只动 k 这一个方向，不影响其它记忆")
    print("  → 这就是「擦除」的数学：沿 k 方向的分量被削弱 1-β 倍，再写入新值 v")


# ============================================================ 2. WY 表示
def demo_wy():
    section("2. WY 表示：把一长串秩1修正压成一个 d×C 矩阵")
    d, C = 6, 5
    torch.manual_seed(3)
    K = torch.randn(C, d); K = K / K.norm(dim=-1, keepdim=True)
    beta = torch.rand(C) * 0.9 + 0.05

    # 直接累乘得到前缀转移矩阵 A_t = T_0 T_1 ... T_t
    I = torch.eye(d)
    As = []
    A = I.clone()
    for t in range(C):
        A = A @ (I - beta[t] * torch.outer(K[t], K[t]))
        As.append(A.clone())

    # WY 表示：A_t = I - W_{0:t} K_{0:t}ᵀ，W 由三角系统解出
    G = K @ K.T                                      # (C,C)
    Gt = torch.tril(G, -1)
    Aw = torch.eye(C) + beta[:, None] * Gt           # (C,C): I + diag(β)·tril(G,-1)
    W = torch.linalg.solve_triangular(Aw, beta[:, None] * K, upper=False)   # (C,d)

    for t in range(C):
        Wy = I - W[:t + 1].T @ K[:t + 1]             # (d,d): I - Σ_{i≤t} w_i k_iᵀ
        check(f"t={t}: Π_{{i≤t}}(I-β_i k_i k_iᵀ) == I - W_{{0:t}}K_{{0:t}}ᵀ", Wy, As[t], atol=1e-5)

    print("  WY 表示（Bischof–Van Loan / LAPACK 紧凑 Householder）:")
    print("    Π_{i≤t}(I - β_i k_i k_iᵀ) = I - W_{0:t} K_{0:t}ᵀ")
    print("    w_t = β_t ( k_t - Σ_{i<t} (k_iᵀk_t) w_i )   ← 下三角递推，等价于三角线性系统")
    print("  → 意义：C 次 d×d 矩阵乘法（O(C d²)，串行） 变成 一次 C×C 三角求解（可 batched、可并行）")
    print("  → 这是 Householder QR 分块化的同一个技巧，被搬到了序列建模里")

def demo_erase_power():
    section("4. 为什么「擦除」能突破秩饱和（对比 CH06）")
    d = 32
    torch.manual_seed(1)
    print("  任务：往状态里塞 n 个 key-value 对，然后回读，看相对误差")
    print(f"  {'n_pairs':>8} {'线性累加':>10} {'gated(α=0.9)':>13} {'Δrule':>10} {'gated Δrule':>13}")
    for n_pairs in [8, 16, 32, 64]:
        Km = torch.randn(n_pairs, d); Km = Km / Km.norm(dim=-1, keepdim=True)
        Vm = torch.randn(n_pairs, d)
        alpha_v = 0.9

        def err(S):
            return sum(((S @ Km[j] - Vm[j]).norm() / Vm[j].norm()).item()
                       for j in range(n_pairs)) / n_pairs

        # ① 线性累加（无擦除、无衰减）
        S1 = sum(torch.outer(Vm[j], Km[j]) for j in range(n_pairs))
        # ② 只有衰减（Mamba2 式：S ← αS + v kᵀ）
        S2 = torch.zeros(d, d)
        for j in range(n_pairs):
            S2 = alpha_v * S2 + torch.outer(Vm[j], Km[j])
        # ③ 只有 Δ rule（无衰减）
        S3 = torch.zeros(d, d)
        for j in range(n_pairs):
            S3 = S3 + torch.outer(Vm[j] - S3 @ Km[j], Km[j])
        # ④ Gated Δ rule（衰减 + 擦除，多遍收敛）
        S4 = torch.zeros(d, d)
        for _ in range(8):
            for j in range(n_pairs):
                v_hat = alpha_v * (S4 @ Km[j])
                S4 = alpha_v * S4 + torch.outer(Vm[j] - v_hat, Km[j])
        print(f"  {n_pairs:>8} {err(S1):>10.3f} {err(S2):>13.3f} {err(S3):>10.3f} {err(S4):>13.3f}")
    print("  → 线性累加在 n > d 时彻底失效；衰减能缓解但会遗忘早期记忆；")
    print("  → Δ rule 主动擦除 k 方向的旧内容，让有限秩反复「复用」，容量显著提升")
    print("  → 注意真实的权衡：α<1 的遗忘会牺牲一部分远期记忆容量，")
    print("     换来处理超长序列时的稳定性。Gated DeltaNet 让 α_t、β_t 都由数据决定，"
          "由模型自己学这个权衡。")

1. MoE 的矩阵写法

MoE 层：每个 token 选 $k$ 个专家（TopK），输出是加权和

$$ y_t = \sum_{i \in \mathrm{TopK}(x_t)} g_i(x_t)\, E_i(x_t) $$

把 $T$ 个 token 按它们被分配到的专家排序后，整层可以写成一个矩阵表达式：

$$ \boxed{Y = P^\top\, \mathrm{blkdiag}\big(E_0, E_1, \dots, E_{E-1}\big)\, P\, X} $$

其中 $P$ 是路由决定的置换矩阵（每行每列恰一个 1）。拆开看：

步骤 数学 工程
① 路由 置换 $P$ argsort + repeat_interleave(topk)
② 专家计算 块对角矩阵乘 GroupGEMM：每个块一次 GEMM，块高 = 该专家分到的 token 数
③ 反置换 + 加权 $P^\top$ + 逐行乘 $g_i$ scatter + 乘权重

置换矩阵的好性质：$P^{-1} = P^\top$，且逆置换可以用 argsort 直接得到 （因为 $P$ 是正交矩阵，$P^\top$ 也是一个置换）。

2. 三种实现及其等价性

ch08 实现了三种，并互相验证：

(a) moe_loop：按专家循环

for e in range(E):
    idx = (expert_id == e)
    out[idx] += g[idx] * expert_ffn(x[idx], E_e)
  • 优点：简单、零 padding；
  • 缺点：$E$ 次 kernel launch，$E$ 很大（DeepSeek 有 256 个专家）时调度开销爆炸； 且每个 GEMM 的 $M$ 很小 → 算术强度低。

(b) moe_grouped：排序 + GroupGEMM

order   = torch.argsort(expert_id)            # 稳定排序，同专家聚在一起
counts  = torch.bincount(expert_id, minlength=E)
offsets = torch.cumsum(counts) - counts       # 每个专家块的起始位置
xs      = x[order]                            # 重排后的输入（连续！）
# 对每个专家切一个 [offset: offset+count] 的连续切片做一次 GEMM
  • 优点：输入连续，能用上高效 GEMM；kernel 数量可控（甚至可以打包成一个 kernel）；
  • 关键：order 是稳定排序（argsort 对相同 key 保持原顺序），所以反置换 argsort(order) 能还原。

⚠️ 踩过的坑：路由权重 $g$ 必须跟着一起重排（或按 order 索引）。 写成 flat_w[order] 才对；漏掉这一步会得到 max|Δ| = 3.4e-01（看起来"差不多"但其实是错的）。

(c) moe_blockdiag：显式块对角

把 $\mathrm{blkdiag}(E_0,\dots,E_{E-1})$ 真的构造出来（或用 one-hot mask 索引）， 一次大矩阵乘。适合教学理解，实际不用（因为块对角矩阵是 $Ed \times Ed$ 的巨大稀疏矩阵）。

ch08 验证三者数值一致（max|Δ| = 0）。

3. Padding vs Ragged：GroupGEMM 的两个流派

各专家分到的 token 数不均（这就是负载不均衡），设最大块大小为 $M_{\max}$：

流派 做法 waste
Padded 所有块补齐到 $M_{\max}$（或对齐到 8/16/64 的倍数），填 0 $(M_{\max} - \bar M)/\bar M$
Ragged 用 offsets 描述变长，kernel 内部按 ragged 索引 0，但 kernel 复杂

ch08 实测（专家块大小 $[135, 129, 122, 126]$，即均衡时）：

对齐粒度 padding 浪费
无对齐 0%
对齐到 128 的倍数 32.1%
对齐到 256 的倍数 65.7%
对齐到 512 的倍数 100.2%

结论：对齐粒度是把双刃剑——tensor core 要求 $M$ 是 8/16 的倍数才高效， 但粒度太大会浪费一半以上算力。工程上一般取 $M$ 对齐到 64 或 128， 或者用 ragged kernel（如 DeepGEMM 的做法）。

4. 负载均衡的辅助损失

如果不加约束，路由会塌缩（所有 token 都去少数几个专家）。经典辅助损失：

$$ \mathcal{L}{aux} = \alpha \cdot E \sum f_e\, P_e $$}^{E

其中：

  • $f_e$ = 分到专家 $e$ 的 token 比例（实际负载）；
  • $P_e$ = 专家 $e$ 的平均路由概率（软负载）。

为什么是 $f \cdot P$ 而不是别的？ 在完全均衡时 $f_e = 1/E$，$P_e = 1/E$，则 $\sum_e f_e P_e = E \cdot (1/E^2) = 1/E$， 乘 $E$ 得 1 —— 所以损失值 1 是"完美均衡"的基准线，越大于 1 越不均。

ch08 实测：

场景 $E\cdot\sum f_e P_e$
均衡路由 1.000
轻度不均 1.136
严重不均 2.510

这个损失在可微上是必要的：$f_e$ 本身是离散的（不可导），所以用连续的 $P_e$ 作为它的"代理"， 再让梯度通过 $P_e$ 传回路由器。

5. 置换矩阵的性质验证

ch08 检查：

  • $P^\top P = I$（正交）
  • $P^{-1} = P^\top$，且 argsort(order) 就是 $P^\top$
  • 正置换 + 反置换 = 恒等

这也是 CH09 DeepEP 里 all-to-all 的数学基础：跨设备的 token 分发就是一个跨设备的置换。

"""

  把所有 token 按分配的专家排序后，整层可以写成一个【块对角矩阵】作用：
      Y = Pᵀ · blkdiag(E_0, E_1, ..., E_{E-1}) · P · X
  其中 P 是路由决定的置换矩阵。因此：
      · 路由 = 置换（对 token 做重排）
      · 专家计算 = 块对角矩阵乘法（每个块是一次 GEMM，块大小 = 该专家分到的 token 数）
      · GroupGEMM = 一组形状各异的 GEMM 打包成一个 kernel

学习目标
  1. 从置换矩阵 + 块对角矩阵理解 MoE 的代数结构
  2. 三种实现：逐专家循环 / padding 成定长 batched GEMM / 紧凑分组（GroupGEMM）
  3. 负载均衡为什么要加辅助损失：从块大小均匀性看 GPU 利用率
  4. 排序（permute）与还原（unpermute）的矩阵写法

import torch
import torch.nn.functional as F

# ------------------------------------------------------------------ 数据
def make_moe(T=1024, d=256, ff=512, E=8, topk=2, seed=0):
    g = torch.Generator().manual_seed(seed)
    x = torch.randn(T, d, generator=g)
    Wg = torch.randn(d, E, generator=g) * 0.1
    W1 = torch.randn(E, d, ff, generator=g) * 0.05      # 每个专家的 up 投影
    W2 = torch.randn(E, ff, d, generator=g) * 0.05      # 每个专家的 down 投影
    return x, Wg, W1, W2


def route(x, Wg, topk=2):
    logits = x @ Wg                                     # (T, E)
    prob = torch.softmax(logits, -1)
    topv, topi = prob.topk(topk, dim=-1)                # (T, topk)
    return topi, topv / topv.sum(-1, keepdim=True)      # 专家 id 与归一化权重


def expert_ffn(x, W1_i, W2_i):
    return F.gelu(x @ W1_i) @ W2_i


# --------------------------------------------------- 实现 1：逐专家循环
def moe_loop(x, Wg, W1, W2, topk=2):
    T, d = x.shape
    E = W1.shape[0]
    topi, w = route(x, Wg, topk)
    out = torch.zeros(T, d)
    for e in range(E):
        mask = (topi == e).any(-1)                      # 分到专家 e 的 token
        if not mask.any():
            continue
        xe = x[mask]                                    # gather
        ye = expert_ffn(xe, W1[e], W2[e])
        out[mask] += w[mask][topi[mask] == e].unsqueeze(-1) * ye   # scatter-add
    return out, topi


# -------------------------- 实现 2：排序 + 分组 GEMM（GroupGEMM 的语义）
def moe_grouped(x, Wg, W1, W2, topk=2, pad_to=None):
    """先按专家排序（置换），再对每个专家做一次 GEMM，最后加权还原（逆置换）。
    这是所有 MoE kernel 的通用套路；真实实现（DeepGEMM / Megablocks）用
    ragged 偏移量把这组变长 GEMM 塞进一个 kernel，避免 padding 浪费。
    """
    T, d = x.shape
    E = W1.shape[0]
    topi, w = route(x, Wg, topk)

    flat_id = topi.reshape(-1)                          # (T*topk,)
    flat_w = w.reshape(-1)
    flat_x = x.unsqueeze(1).expand(T, topk, d).reshape(T * topk, d)   # 每个 (token,专家) 一份

    order = flat_id.argsort()                           # 置换：按专家 id 排序
    xs = flat_x[order]
    ids_sorted = flat_id[order]
    counts = torch.bincount(flat_id, minlength=E)       # 每个专家的 token 数
    offsets = torch.cat([torch.zeros(1, dtype=torch.long), counts.cumsum(0)])

    ys = torch.zeros_like(xs)
    for e in range(E):
        s, t = offsets[e].item(), offsets[e + 1].item()
        if t > s:
            ys[s:t] = expert_ffn(xs[s:t], W1[e], W2[e])

    # 逆置换 + 按 token 加权求和
    # xs[j] = flat_x[order[j]]，所以权重也要跟着置换：ys[j] 配 flat_w[order[j]]
    out = torch.zeros(T * topk, d)
    out[order] = ys * flat_w[order].unsqueeze(-1)       # scatter 回原顺序
    return out.view(T, topk, d).sum(1), counts, order, offsets


# --------------------------- 实现 3：块对角矩阵（纯矩阵视角，教学用）
def moe_blockdiag(x, Wg, W1, W2, topk=2):
    """把路由后的计算写成块对角矩阵乘法：
        Y = Σ_e (X ⊙ m_e) · W_e      ⟺   X_ext · blkdiag(W_e)  再按块求和
    其中 X_ext 把 token 复制 E 份并只在对应块放非零值。
    """
    T, d = x.shape
    E, ff = W1.shape[0], W1.shape[2]
    topi, w = route(x, Wg, topk)

    # 构造块对角权重 (E*d, E*ff)
    Wb1 = torch.zeros(E * d, E * ff)
    Wb2 = torch.zeros(E * ff, E * d)
    for e in range(E):
        Wb1[e * d:(e + 1) * d, e * ff:(e + 1) * ff] = W1[e]
        Wb2[e * ff:(e + 1) * ff, e * d:(e + 1) * d] = W2[e]

    out = torch.zeros(T, d)
    for k in range(topk):
        e_ids = topi[:, k]                                        # (T,) 第 k 个专家的选择
        mask = torch.zeros(T, E)
        mask.scatter_(1, e_ids[:, None], 1.0)                     # one-hot
        Xext = (mask.unsqueeze(-1) * x.unsqueeze(1)).reshape(T, E * d)   # 只在对应块非零
        H = Xext @ Wb1                                            # 块对角乘法 (T, E*ff)
        Y = F.gelu(H) @ Wb2                                       # (T, E*d)
        Yk = Y.view(T, E, d).gather(1, e_ids[:, None, None].expand(T, 1, d)).squeeze(1)
        out += Yk * w[:, k:k + 1]                                 # 加权求和
    return out

1. 专家并行 = 跨设备的置换

CH08 里，MoE 在一个设备上是 $Y = P^\top \mathrm{blkdiag}(E_e)\, P X$。 专家并行（EP）把这些专家分到不同 GPU 上，于是 $P$ 变成跨设备的置换：

设备 0 的 token ──┐
设备 1 的 token ──┼─→ All-to-All ─→ 每个设备收到"属于自己专家"的 token
设备 2 的 token ──┤                 （各设备收到的数量不同 → 变长！）
设备 3 的 token ──┘

All-to-All 的定义：每个设备把发送缓冲的第 $j$ 块发给设备 $j$，同时从第 $j$ 个设备接收第 $i$ 块。 它就是一个块置换矩阵作用于分布式张量。

ch09 的 simulate_alltoall 在单进程里模拟：

flat_x = x.repeat_interleave(topk, dim=0)    # ⚠️ token 被复制 topk 份！
order  = torch.argsort(expert_id)            # 按目标专家排序 → 即"发送顺序"
ys     = expert_ffn(flat_x[order], ...)      # 本地计算
recv   = torch.zeros_like(flat_x)
recv[order] = ys                             # 反置换 = 接收回本地

⚠️ 踩过的坑：必须先 repeat_interleave(topk)。 topk=2 时每个 token 去 2 个专家，发送缓冲是 $2T$ 行而不是 $T$ 行。 漏掉会得到 IndexError: index 60 is out of bounds for dimension 0 with size 32。

2. 通信量的账

设：$T$ token、topk=$k$、隐层 $d$、EP 度 $W$。

每步发送量：$T \cdot k \cdot d \cdot (\text{bytes})$（bf16 = 2 字节）。 往返（dispatch + combine）是 2 倍。

ch09 实测（$T{=}4096$, topk=2, $d{=}4096$, bf16）：

项 数值
通信量（dispatch + combine） 67.1 MB
按 400 Gb/s (50 GB/s) 计 1.34 ms
专家计算量 2886.2 GFLOP
按 300 TFLOP/s 计 9.62 ms
计算/通信比 7.17
换成 FP8（通信减半） 14.34

结论：EP 的通信量只与 $T \cdot k \cdot d$ 有关，与专家数 $E$、EP 度无关。 所以可以放心地把专家数堆到 256（DeepSeek-V3）—— 代价是每步通信延迟（latency）不变， 但要保证 batch 足够大才能让通信被计算掩盖。小 batch 推理时 EP 就很不划算。

3. FP8 (e4m3) 量化：为什么是它

FP8 有两种格式：

格式 指数位 尾数位 用途
e4m3 4 3 权重/激活（前向）
e5m2 5 2 梯度（反向，动态范围优先）

e4m3 的相对精度：3 位尾数 ⇒ 有效数字约 $1 + 2^{-3}$，即相对步长 $2^{-3} = 12.5\%$？ 不对——尾数 $m$ 位意味着相对误差约 $2^{-(m+1)} = 2^{-4} = 6.25\%$（舍入到最近）。 实际表现：

  • 正规数区间：相邻可表示数的步长是 $2^{e-3}$，相对步长 $2^{-3}$；
  • 次正规（subnormal）区间：步长被钉在 $2^{-9}$（e4m3 的最小次正规 = $2^{-9}$）。

ch09 的 fp8_e4m3_emulate 精确模拟了这两段：

step = torch.where(a >= 2**-6, 2**(e - 3), 2**-9)    # 正规 / 次正规

这个"次正规地板"很重要：它让 FP8 在极小数上绝对误差有界， 也解释了为什么 FP8 在小幅度张量上比 INT8 好得多。

FP8 vs INT8

FP8 e4m3 INT8
表示 浮点（指数 + 尾数） 定点仿射 $q = \mathrm{round}(x/s) + z$
相对误差 全程近似恒定（~6%） 与幅度成反比（小数相对误差爆炸）
动态范围 靠指数，天生很大 靠 scale，需分块
硬件 Hopper/Blackwell tensor core 原生支持 老硬件也有

ch09 第 3 节用一个混合幅度张量（一小段极小值 + 一大段大值，动态范围 $5.19\times 10^4$）对比：

方法 小值段相对误差 大值段相对误差
FP8 per-tensor 27.7% ——
INT8 per-tensor 100.0% ——
FP8 block-wise (128) 2.56% 2.56%
INT8 block-wise (128) 0.65% 0.64%

这就是 block-wise scaling 的全部动机：一个 scale 管不住 $10^5$ 的动态范围， 把张量切成 128 元素的小块、每块一个 scale，误差直接降一个数量级。

DeepEP / DeepGEMM 用的正是 per-128-element block-wise scaling（配合 Hopper 的 MX 格式思路）。注意 scale 的取值：$s = \mathrm{amax}/448$（448 = e4m3 的最大值）， 不是 $448/\mathrm{amax}$ —— 这个方向搞反会得到 100% 误差（本教程踩过）。

4. 量化误差会不会随 $K$ 累积？

GEMM $c = \sum_{k=1}^K a_k b_k$。若每个 $a_k,b_k$ 有独立量化噪声 $\epsilon$， 则结果的相对误差不随 $K$ 增长：

$$ \lVert a\cdot b\rVert \propto \sqrt{K},\qquad \text{噪声} \propto \sqrt{K}\ \Rightarrow\ \text{相对误差} \propto O(1) $$

ch09 实测：不同 $K$ 下 GEMM 的相对误差稳定在 ~3.73%，确实不累积。

这是量化能用在 GEMM 上的理论基础。（对比：如果误差是乘性的、或存在系统性偏置， 就会随 $K$ 或层数累积 —— 所以要特别小心"零点/偏置"的处理。）

5. 计算-通信重叠

EP 的瓶颈是：dispatch（通信）→ 计算 → combine（通信）。 如果串行执行，总时间 = $T_{comm} + T_{comp} + T_{comm}$。

Dual-stream / chunk 流水线：把 token 流切成小块，两块交替：

stream A:  [comm chunk0][comp chunk0][comm chunk0']
stream B:        [comm chunk1][comp chunk1][comm chunk1']

当 chunk 数足够多时，通信几乎完全被计算掩盖，总时间 $\to \max(T_{comm}, T_{comp})$。

ch09 的 demo_overlap 用"分块数 vs 总耗时"的表格演示了这个收敛过程。

工程要点：

  • chunk 太小 → 通信的延迟（而非带宽）无法掩盖（每块都有固定开销）；
  • chunk 太大 → 掩盖不完全；
  • DeepEP 提供 normal（训练/prefill，高吞吐）和 low-latency（推理 decode， 纯 RDMA、无 SM 占用）两种模式，就是针对这两个极端。

# ------------------------------------------------- 1. 模拟 All-to-All
def simulate_alltoall(x_local, dst_expert, E, W_dev):
    """模拟 EP 的 dispatch：每个设备持有一批 token，按目标专家分组后"发送"。
    真实实现用 NCCL/RDMA All-to-All；这里用索引操作表达同样的语义。
    x_local: (W_dev, T_loc, d)   dst_expert: (W_dev, T_loc, topk)
    返回: 每个专家收到的 token 拼接 (E, *, d) 以及各专家的 token 数
    """
    Wd, T_loc, d = x_local.shape
    topk = dst_expert.shape[-1]
    # 每个 (token, 专家选择) 对都要发一份 ⇒ token 复制 topk 份
    flat_x = x_local.reshape(Wd * T_loc, d).repeat_interleave(topk, dim=0)
    flat_e = dst_expert.reshape(-1)
    order = flat_e.argsort()
    xs = flat_x[order]
    counts = torch.bincount(flat_e, minlength=E)
    offsets = torch.cat([torch.zeros(1, dtype=torch.long), counts.cumsum(0)])
    return xs, counts, offsets, order


def demo_alltoall():

# --------------------------------------------------------- 3. FP8 量化
def fp8_e4m3_emulate(x, scale):
    """模拟 e4m3（4 指数位 + 3 尾数位）的量化：相对步长 2^-3，最大正规数 448。
    x_hat = scale · round_fp8(x / scale)
    """
    q = x / scale
    q = q.clamp(-448.0, 448.0)
    sign = torch.sign(q)
    a = q.abs().clamp(min=1e-30)
    # 正规区：步长 = 2^{e-3}（3 位尾数）；次正规区（|q| < 2^-6）：步长固定 2^-9，低于它直接归零
    e = torch.floor(torch.log2(a))
    step = torch.where(a >= 2.0 ** -6, torch.pow(2.0, e - 3), torch.full_like(a, 2.0 ** -9))
    return sign * torch.round(a / step) * step * scale


def blockwise_amax(x, block=128):
    """按连续 block 个元素分组，每组一个 amax（DeepGEMM/DeepEP 用 128 元素块）"""
    n = x.numel()
    pad = (-n) % block
    xf = torch.cat([x.reshape(-1), torch.zeros(pad, dtype=x.dtype)]) if pad else x.reshape(-1)
    amax = xf.view(-1, block).abs().amax(-1)
    return amax


def int8_quantize(x, scale):
    """均匀（仿射）量化：q = round(x/s)，s = amax/127。相对误差 ∝ 1/|x| —— 小值最吃亏"""
    q = torch.round(x / scale).clamp(-128, 127)
    return q * scale

1. Eckart–Young 定理：低秩近似的理论基石

定理（Eckart–Young–Mirsky）：设 $A$ 的奇异值 $\sigma_1\ge\sigma_2\ge\cdots$，则

$$ \min_{\mathrm{rank}(B)\le r}\ \lVert A - B\rVert_F = \sqrt{\sum_{i>r}\sigma_i^2} $$

且最优解就是截断 SVD：

$$ A_r = \sum_{i=1}^r \sigma_i u_i v_i^\top = U_r \Sigma_r V_r^\top $$

推论：低秩近似的效果完全由奇异值的尾部能量决定。 定义"保留能量比"：

$$ \eta(r) = \frac{\sum_{i\le r}\sigma_i^2}{\sum_i \sigma_i^2} $$

ch10 第 1 节构造一个谱按 $\exp(-i/6)$ 衰减的矩阵，实测截断 SVD 的误差 与 $\sqrt{\sum_{i>r}\sigma_i^2}$ 吻合（max|Δ| ≈ 1.2e-07）。

LoRA 的秩怎么选

LoRA 假设微调的更新 $\Delta W$ 是低秩的：$\Delta W = BA$，$B\in\mathbb{R}^{d_{out}\times r}, A\in\mathbb{R}^{r\times d_{in}}$。

  • $r$ 太小 → 表达力不足（$\eta(r)$ 太低）；
  • $r$ 太大 → 参数量与全量微调接近，失去意义。

经验法则：看 $\Delta W$ 的谱衰减速度。如果前 $r$ 个奇异值就吃掉 90% 能量， $r$ 就够了。ch10 第 2 节用真实谱衰减（指数衰减 vs 均匀谱）对比了不同 $r$ 的逼近误差。

注意：要评估的是 $\Delta W$ 的谱，不是 $W$ 的谱！ 预训练权重 $W$ 的谱通常很"平"（信息均匀分布），而 $\Delta W$ 的谱往往很"尖"。 ch10 里特意对比了"重建整个 $W$"和"重建 $\Delta W$"两种误差。

2. MLA：多层注意力 = 把 KV 压进一个低秩潜向量

MLA（Multi-head Latent Attention，DeepSeek-V2/V3） 的核心： 不缓存每个头的 $K, V$，而是缓存一个共享的低秩潜向量 $c_{KV}$。

展开版

$$ c_{KV} = x W_{DKV}\quad (\text{下投影到 } d_c),\qquad \begin{cases} k^{(h)} = c_{KV} W_{UK}^{(h)}\ v^{(h)} = c_{KV} W_{UV}^{(h)}\end{cases} $$

吸收版（推理时的关键技巧）

QK 方向：

$$ q^{(h)\top} k^{(h)} = \big(W_{UQ}^{(h)} c_q\big)^\top \big(W_{UK}^{(h)} c_{KV}\big) = c_q^\top \underbrace{\big(W_{UQ}^{(h)\top} W_{UK}^{(h)}\big)}{\text{预先合并成一个 } d_c\times d_c} c $$

把两个矩阵预先乘好，推理时直接用合并矩阵 —— 省掉一次投影。

输出方向（更妙）：

$$ \sum_h W_O^{(h)}\, A^{(h)}\, \big(W_{UV}^{(h)} c_{KV}\big) = \sum_h \big(A^{(h)} c_{KV}\big)\underbrace{\big(W_{UV}^{(h)} W_O^{(h)}\big)}_{\text{合并}} $$

注意 $A^{(h)}$ 是 $N\times N$ 的注意力矩阵，这一步把"先投影 V 再乘 $W_O$" 换成了"先做 attention 加权再一次性投影" —— 顺序换了，乘的矩阵变少了。

ch10 验证：展开版 == 吸收版，max|Δ| = 2.235e-08。

解耦 RoPE：为什么必须留 $d_r$ 维

问题：RoPE 是位置相关的旋转，它和"低秩潜向量"不兼容。

$$ \big\langle \rho(m)W_{UQ}c_q,\ \rho(n)W_{UK}c_{KV}\big\rangle \ne c_q^\top (\text{某个固定矩阵})\, c_{KV} $$

因为 $\rho(m)$ 插在中间，且依赖 $m$ —— 无法吸收进一个与位置无关的矩阵。

解决办法：把 $q, k$ 拆成两部分：

$$ q = [\underbrace{q^{C}}{\text{可压缩部分}},\ \underbrace{q^{R}}],\qquad k = [k^{C},\ k^{R}] $$}

  • $q^C, k^C$ 走低秩潜向量（可吸收、可压缩）；
  • $q^R, k^R$（$d_r = 64$ 维）单独做 RoPE，每个头都要缓存。

所以 MLA 的 KV Cache = $d_c + d_r$ per token，而不是 $2\cdot H\cdot D$。

3. 权重量化：从 INT8 到 INT2

仿射量化

$$ \hat w = s\cdot\big(\mathrm{clamp}(\mathrm{round}(w/s) + z,\ -2^{b-1},\ 2^{b-1}-1) - z\big) $$

  • per-tensor：整个张量一个 $(s,z)$；
  • per-channel（按输出通道）：每个输出通道一个 —— 通常用这个；
  • per-group（每 $g$ 个元素）：$g=32/64/128$，精度与开销的折中。

ch10 第 4 节实测 $y = x\hat W^\top$ 的相对误差：

位宽 per-tensor group=128 group=32
INT8 1.080% 0.646% 0.533%
INT4 19.586% 11.709% 9.688%
INT3 45.715% 27.335% 22.584%
INT2 97.181% 76.568% 65.526%

两个观察：

  1. 均匀量化的理论误差 $\approx \dfrac{\mathrm{step}/\sqrt{12}}{\sigma}$，$\mathrm{step} = \dfrac{2\,\mathrm{amax}}{2^b-1}$。 对高斯权重，INT8 ≈ 1%，INT4 ≈ 10% —— 和实测吻合。
  2. 光靠均匀量化，INT4 的 19.6% 是完全不能用的。 真实模型能跑 INT4 甚至 INT2，靠的是把目标从 $\lVert W-\hat W\rVert_F$ 换掉（见下节）。
  3. group 越小误差越低，但 scale 的存储和访存开销越大 —— 实践中 group=32/64/128 是常见折中。

为什么需要 Hessian 加权（GPTQ / AWQ）

关键洞察：不是所有权重的误差都同等重要。

考虑损失函数对权重的二阶近似：$\Delta L \approx \frac12 \Delta w^\top H\, \Delta w$， 其中 $H = \mathbb{E}[xx^\top]$ 是输入特征的二阶矩（Hessian 的近似）。

所以量化目标不是 $\min\lVert W - \hat W\rVert_F$，而是

$$ \min_{\hat W}\ \big(W - \hat W\big)^\top H \big(W - \hat W\big) $$

含义：

  • 若某个权重对应的输入特征方差很大（$H$ 的对角元大）→ 它的误差被放大 → 要保留高精度；
  • AWQ 据此对重要通道乘一个放大系数 $s$（再在别处除回来），等效于给它们更多"量化级数"；
  • GPTQ 则是逐个量化权重，并把当前权重的量化误差按 $H^{-1}$ 分配到后面的未量化权重上（OBQ 的加速版）。

ch10 用对角 Hessian 的加权目标演示了这一点：同样位宽下，Hessian 加权的目标 在"模型输出误差"上明显优于普通 Frobenius 目标。

4. 三个技巧的关系

技巧 数学工具 作用

共同点：它们都在问"这个矩阵真正需要多少信息量"， 而答案分别由奇异值谱（LoRA/MLA）和 Hessian 谱（量化）给出。

# ------------------------------------------------------------ 3. MLA
class MLA(torch.nn.Module):
    """Multi-head Latent Attention（DeepSeek-V2/V3 的核心）

    训练/展开版（便于理解）:
        c_KV = x W_DKV            (d_model → d_c)    低秩 KV 压缩
        c_Q  = x W_DQ             (d_model → d_cq)
        K    = c_KV W_UK          (d_c  → H·d_h)     上采样
        V    = c_KV W_UV
        Q    = c_Q  W_UQ
    推理/吸收版（不展开 K、V，KV cache 只存 c_KV 与 k_r）:
        score = c_Qᵀ (W_UQᵀ W_UK) c_KV        ← W_UK 被吸收进 W_UQ
        out   = Σ_h (A_h c_KV) (W_UV_h W_O_h) ← W_UV 被吸收进 W_O
    """

    def __init__(self, d_model=256, H=8, d_h=32, d_c=64, d_cq=96, d_r=32):
        super().__init__()
        self.d_model, self.H, self.d_h, self.d_c, self.d_r = d_model, H, d_h, d_c, d_r
        self.W_DKV = torch.nn.Parameter(torch.randn(d_model, d_c) * 0.02)
        self.W_DQ = torch.nn.Parameter(torch.randn(d_model, d_cq) * 0.02)
        self.W_UQ = torch.nn.Parameter(torch.randn(d_cq, H * d_h) * 0.02)
        self.W_UK = torch.nn.Parameter(torch.randn(d_c, H * d_h) * 0.02)
        self.W_UV = torch.nn.Parameter(torch.randn(d_c, H * d_h) * 0.02)
        self.W_O = torch.nn.Parameter(torch.randn(H * d_h, d_model) * 0.02)
        # 解耦 RoPE 部分（不进 latent，避免位置信息被低秩压缩破坏）
        self.W_QR = torch.nn.Parameter(torch.randn(d_model, H * d_r) * 0.02)
        self.W_KR = torch.nn.Parameter(torch.randn(d_model, d_r) * 0.02)
        self.d_cq = d_cq

    def forward(self, x, rope_cos=None, rope_sin=None, absorbed=True):
        B, N, _ = x.shape
        H, d_h, d_r = self.H, self.d_h, self.d_r
        c_kv = x @ self.W_DKV                                   # (B,N,d_c)
        c_q = x @ self.W_DQ                                     # (B,N,d_cq)
        q_r = (x @ self.W_QR).view(B, N, H, d_r)                # 解耦 RoPE 的 q
        k_r = x @ self.W_KR                                     # (B,N,d_r)

        if rope_cos is not None:                                # 对解耦部分施加 RoPE
            def rot_half(t):
                t1, t2 = t.chunk(2, -1)
                return torch.cat((-t2, t1), -1)
            q_r = q_r * rope_cos[None, :, None, :] + rot_half(q_r) * rope_sin[None, :, None, :]
            k_r = k_r * rope_cos[None, :, :] + rot_half(k_r) * rope_sin[None, :, :]

        if not absorbed:                                        # 展开版（教学对照）
            q = (c_q @ self.W_UQ).view(B, N, H, d_h)
            k = (c_kv @ self.W_UK).view(B, N, H, d_h)
            v = (c_kv @ self.W_UV).view(B, N, H, d_h)
            s = torch.einsum("bnhd,bmhd->bhnm", q, k) * d_h ** -0.5
            s = s + torch.einsum("bnhd,bmd->bhnm", q_r, k_r) * (d_h + d_r) ** -0.5
            mask = torch.triu(torch.ones(N, N, dtype=torch.bool), 1)
            s = s.masked_fill(mask, float("-inf"))
            a = torch.softmax(s, -1)
            o = torch.einsum("bhnm,bmhd->bnhd", a, v).reshape(B, N, H * d_h)
            return o @ self.W_O

        # ---- 吸收版 ----
        # ① W_UK 吸收进 W_UQ：score_h = c_qᵀ (W_UQ_hᵀ W_UK_h) c_kv
        W_UQh = self.W_UQ.view(self.d_cq, H, d_h)
        W_UKh = self.W_UK.view(self.d_c, H, d_h)
        W_absorb = torch.einsum("chd,C hd->hcC", W_UQh, W_UKh)   # (H, d_cq, d_c)
        s = torch.einsum("bnc,hcC,bmC->bhnm", c_q, W_absorb, c_kv) * d_h ** -0.5
        s = s + torch.einsum("bnhd,bmd->bhnm", q_r, k_r) * (d_h + d_r) ** -0.5
        mask = torch.triu(torch.ones(N, N, dtype=torch.bool), 1)
        s = s.masked_fill(mask, float("-inf"))
        a = torch.softmax(s, -1)                                 # (B,H,N,N)
        # ② W_UV 吸收进 W_O：out = Σ_h (A_h c_kv) (W_UV_h W_O_h)
        Z = torch.einsum("chd,hdD->hcD", self.W_UV.view(self.d_c, H, d_h),
                         self.W_O.view(H, d_h, self.d_model))    # (H, d_c, d_model)
        ac = torch.einsum("bhnm,bmc->bhnc", a, c_kv)             # (B,H,N,d_c)
        return torch.einsum("bhnc,hcD->bnD", ac, Z)


def demo_mla():
    section("3. MLA：低秩 KV 压缩 + 矩阵吸收")
    B, N, d_model = 2, 64, 256
    H, d_h, d_c, d_r = 8, 32, 64, 32
    x = torch.randn(B, N, d_model)
    mla = MLA(d_model=d_model, H=H, d_h=d_h, d_c=d_c, d_cq=96, d_r=d_r)

    # 简易 RoPE（半分布局）

1. 张量并行：把权重矩阵按行/列切开

一切分布式并行的数学本质都是分块矩阵。

设 $X\in\mathbb{R}^{T\times d_{in}}$，$W\in\mathbb{R}^{d_{in}\times d_{out}}$，$Y = XW$。

列切分（Column Parallel）

把 $W$ 按输出维切成 $W = [W_1\ \cdots\ W_n]$，每块 $(d_{in},\ d_{out}/n)$：

$$ Y = X\,[W_1\ \cdots\ W_n] = [XW_1\ \cdots\ XW_n] $$

  • 每卡需要完整的 $X$；
  • 输出天然是拼接 ⇒ 零通信（输入若已复制）。

行切分（Row Parallel）

把 $W$ 按输入维切成 $W = [W_1; \cdots; W_n]$，每块 $(d_{in}/n,\ d_{out})$：

$$ Y = [X_1\ \cdots\ X_n]\begin{bmatrix}W_1\ \vdots\ W_n\end{bmatrix} = \sum_i X_i W_i $$

  • 每卡只需要对应的 $X_i$（$X$ 按特征维切好）；
  • 输出是部分和 ⇒ 需要一次 all-reduce。

⚠️ 本教程踩过的坑：行切分时如果只切 $W$ 不切 $X$，x @ w 会直接报 mat1 and mat2 shapes cannot be multiplied (64x256 and 64x512)。 记住：行切要求输入同步按特征维切分 —— 这正是它能直接接在列切后面的原因。

Megatron 的 MLP 并行

MLP：$Y = \mathrm{GeLU}(XA)\,B$，$A:(d,\ 4d)$，$B:(4d,\ d)$。

$$ \begin{aligned} A &\xrightarrow{\text{列切}} [A_1\ \cdots\ A_n] &&\Rightarrow XA = [XA_1\ \cdots\ XA_n]\ \text{（无需通信）}\ B &\xrightarrow{\text{行切}} [B_1; \cdots; B_n] &&\Rightarrow \text{每卡算 } \mathrm{GeLU}(XA_i)B_i\ Y &= \sum_i \mathrm{GeLU}(XA_i)B_i &&\Rightarrow \text{最后 all-reduce 一次} \end{aligned} $$

为什么 GeLU 不用通信？ 因为 GeLU 是逐元素非线性，它要求"被切的那一维是完整的"。 $A$ 按列切 ⇒ $XA$ 按列分成 $n$ 块，每块内部完整 ⇒ GeLU 可以就地算。

反过来（$A$ 行切、$B$ 列切）：$XA$ 是部分和，要先 all-reduce 才能过 GeLU ⇒ 多一次通信。

ch11 实测通信量（$T{=}64, d{=}256$，bf16）：

方案 通信量
一次 all-reduce（输出 $T\times d$） 32.0 KB
一次 all-gather（中间激活 $T\times 4d$） 128.0 KB

差 4 倍 —— 这就是 Megatron 选"列切 + 行切"的原因。

2. Ring Attention：在线 softmax 的分布式版本

CH05 的在线 softmax 用在块上；Ring Attention 把它用在设备上。

设定：$W$ 个设备，设备 $i$ 持有 $Q_i, K_i, V_i$（各自的 $\frac{N}{W}$ 行）。

for step in range(W):
    src = (i - step) % W          # 设备 i 本轮收到来自 src 的 K/V
    K_j, V_j = K[src], V[src]
    S = Q_i K_j^T / sqrt(d)       # (N/W, N/W) —— 永远是这么大
    if causal: mask 掉 k 的全局位置 > q 的全局位置
    在线 softmax 更新 (m, l, O)
O = O / l

关键：每个设备上的注意力矩阵永远只有 $(N/W)^2$ 大小 —— 显存与 $N$ 无关（对固定 $W$）。

ch11 验证：

检查 max|Δ|
非因果 Ring == 全局注意力 2.98e-07
因果 Ring == 全局因果注意力 3.58e-07

因果时的负载不均

设备 $i$ 需要来自设备 $0..i$ 的 K/V ⇒ 设备 0 只读 1 块，设备 $W-1$ 要读全部 $W$ 块。 平均利用率只有约 50%。

解决：ZigZag / striped 分区 —— 把序列块按 "$i$ 与 $W-1-i$ 配对"重排 （设备 $i$ 分到第 $i$ 块和第 $W-1-i$ 块），使每个设备的有效步数均衡。

通信量

每步传 $\frac{N}{W}\cdot d$ 的 K/V，共 $W$ 步 ⇒ 总 $\approx N\cdot d$， 与单卡 KV 总量同阶 —— 不随 $N^2$ 增长，这是它能做超长上下文的原因。

# --------------------------------------------------- 2. Ring Attention
def ring_attention(Q, K, V, world=4, causal=False):
    """Ring Attention：world 个设备各持一段 Q/K/V，环形传递 K/V，用在线 softmax 累加。
    与 CH05 的 FlashAttention 用的是同一套 m/ℓ/O 递推，只是"块"变成了"设备上的段"。
    """
    N, d = Q.shape
    assert N % world == 0
    b = N // world
    Qb = Q.reshape(world, b, d)
    Kb = K.reshape(world, b, d)
    Vb = V.reshape(world, b, d)

    O = torch.zeros(world, b, d)
    m = torch.full((world, b, 1), NEG)
    l = torch.zeros(world, b, 1)
    for step in range(world):
        # 第 step 步：设备 i 收到来自设备 (i - step) mod world 的 K/V
        src = torch.tensor([(i - step) % world for i in range(world)])
        Kj, Vj = Kb[src], Vb[src]                          # (world, b, d)
        S = torch.bmm(Qb, Kj.transpose(1, 2)) * d ** -0.5  # (world, b, b)
        if causal:
            # 设备 i 的 query 全局位置 [i*b, (i+1)*b)，key 来自设备 src，位置 [src*b, ...)
            qi = torch.arange(world).view(world, 1, 1) * b + torch.arange(b).view(1, b, 1)
            kj = src.view(world, 1, 1) * b + torch.arange(b).view(1, 1, b)
            S = S.masked_fill(kj > qi, NEG)
        m_new = torch.maximum(m, S.max(-1, keepdim=True).values)
        corr = torch.nan_to_num(torch.exp(m - m_new), nan=0.0)
        P = torch.exp(S - m_new)
        l = l * corr + P.sum(-1, keepdim=True)
        O = O * corr + torch.bmm(P, Vj)
        m = m_new
    return (O / l).reshape(N, d)


def demo_ring():
    section("2. Ring Attention：把在线 softmax 用到跨设备")

class MiniBlock(torch.nn.Module):
    """一个把前 10 章组件都用上的 Transformer 块：
    RMSNorm(γ 已吸收) → GQA 注意力(分块 Flash + RoPE) → SwiGLU MLP
    """

    def __init__(self, d_model=128, H=8, Hkv=2, d_h=16, ff=256, bq=64, bk=64):
        super().__init__()
        self.d_model, self.H, self.Hkv, self.d_h = d_model, H, Hkv, d_h
        self.bq, self.bk = bq, bk
        self.W_Q = torch.nn.Parameter(torch.randn(d_model, H * d_h) * 0.02)
        self.W_K = torch.nn.Parameter(torch.randn(d_model, Hkv * d_h) * 0.02)
        self.W_V = torch.nn.Parameter(torch.randn(d_model, Hkv * d_h) * 0.02)
        self.W_O = torch.nn.Parameter(torch.randn(H * d_h, d_model) * 0.02)
        self.W_up = torch.nn.Parameter(torch.randn(d_model, ff) * 0.02)
        self.W_gate = torch.nn.Parameter(torch.randn(d_model, ff) * 0.02)
        self.W_down = torch.nn.Parameter(torch.randn(ff, d_model) * 0.02)
        self.gamma1 = torch.nn.Parameter(torch.ones(d_model))
        self.gamma2 = torch.nn.Parameter(torch.ones(d_model))

    def rmsnorm(self, x, gamma, eps=1e-6):
        return x * torch.rsqrt(x.pow(2).mean(-1, keepdim=True) + eps) * gamma

    def rope(self, t, cos, sin):
        t1, t2 = t.chunk(2, -1)
        return torch.cat((t1 * cos - t2 * sin, t2 * cos + t1 * sin), -1)

    def flash_causal(self, q, k, v):
        """分块因果注意力（CH05），q,k,v: (N, H, d_h)；内部按 (H, 块, d) 布局以适配 einsum"""
        N, H, d = q.shape
        bq, bk = self.bq, self.bk
        O = torch.zeros(N, H, d)
        for i in range(0, N, bq):
            hi = min(i + bq, N)
            qi = q[i:hi]                                    # (bq, H, d)
            Oi = torch.zeros(H, hi - i, d)
            mi = torch.full((H, hi - i, 1), NEG)
            li = torch.zeros(H, hi - i, 1)
            for j in range(0, hi, bk):          # 因果：只需扫到当前 Q 块右端
                hj = min(j + bk, N)
                S = torch.einsum("qhd,khd->hqk", qi, k[j:hj]) * d ** -0.5
                rows = torch.arange(i, hi).view(1, -1, 1)   # 全局 query 位置
                cols = torch.arange(j, hj).view(1, 1, -1)   # 全局 key 位置
                S = S.masked_fill(cols > rows, NEG)
                m_new = torch.maximum(mi, S.max(-1, keepdim=True).values)
                corr = torch.nan_to_num(torch.exp(mi - m_new), nan=0.0)
                P = torch.exp(S - m_new)
                li = li * corr + P.sum(-1, keepdim=True)
                Oi = Oi * corr + torch.einsum("hqk,khd->hqd", P, v[j:hj])
                mi = m_new
            O[i:hi] = (Oi / li).transpose(0, 1)             # 回到 (块, H, d)
        return O

    def forward(self, x, cos, sin):
        N = x.shape[-2]                                       # 单条序列 (N, d_model)
        H, Hkv, d_h, g = self.H, self.Hkv, self.d_h, self.H // self.Hkv
        h = self.rmsnorm(x, self.gamma1)
        q = (h @ self.W_Q).view(N, H, d_h)
        k = (h @ self.W_K).view(N, Hkv, d_h)
        v = (h @ self.W_V).view(N, Hkv, d_h)
        q = self.rope(q, cos[:, None, :], sin[:, None, :])
        k = self.rope(k, cos[:, None, :], sin[:, None, :])
        k = k.unsqueeze(2).expand(N, Hkv, g, d_h).reshape(N, H, d_h)   # GQA 广播（CH04）
        v = v.unsqueeze(2).expand(N, Hkv, g, d_h).reshape(N, H, d_h)
        o = self.flash_causal(q, k, v).reshape(N, H * d_h) @ self.W_O
        x = x + o
        h2 = self.rmsnorm(x, self.gamma2)
        x = x + (F.silu(h2 @ self.W_gate) * (h2 @ self.W_up)) @ self.W_down
        return x


def demo_capstone():

    print("  组件清单:")

贯穿全书的三个万能技巧

  1. 重缩放对齐 —— 不同块/设备的局部结果，靠一个标量因子 $e^{m_{old}-m_{new}}$ 对齐后累加。 出现在 CH05（在线 softmax）、CH07（chunkwise 状态传递）、CH11（Ring Attention）。
  2. 矩阵吸收 —— 把邻近的对角/标量/小矩阵预先乘进权重，运行时代价为零。 出现在 CH02（$\gamma$、LoRA）、CH05（$\log_2 e$ 吸收进 $1/\sqrt d$）、CH10（MLA）。
  3. 分块 —— 把 $O(N^2)$ 内存切成块，把串行递推变成"块内并行 + 块间传递"。 出现在 CH01、CH05、CH06、CH07、CH08、CH11。
